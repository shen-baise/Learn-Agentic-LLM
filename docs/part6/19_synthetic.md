
# 智能体 LLM 训练中的合成数据生成

## 本章学习目标

在本章中，你将了解合成数据（Synthetic Data）在智能体大语言模型开发中所扮演的角色。具体而言，你将能够：

- 描述*数据*在 LLM 训练流程中的重要性。
- 解释从更强模型中*蒸馏知识*（Knowledge Distillation）到较弱学生模型的一般循环。
- 描述合成数据被用作人类生成内容替代方案的*流程组件*。
- 概述*筛选和评估*合成数据的各种策略。
- 通过描述使用人工生成数据的*风险*，对比使用合成数据的优势与劣势。

## 19.1 数据的重要性

大语言模型的快速扩展带来了对训练和评估数据的巨大需求。有人将训练数据称为*数字石油*，反映了其作为 AI 发展核心要素的重要性。此外，数据正日益成为一个差异化因素，因为流程中的其他组件（如模型架构）正在趋于同质化 [Kim et al., 2025a]。随着模型规模持续增长，它们需要数万亿词的人类生成文本——这些数据从互联网上抓取而来；然而，可用的人类生成数据总量是有限的，这引发了训练数据是否会成为扩展的主要瓶颈这一问题，参见图 19.1 [Villalobos et al., 2024]。而且，随着数据需求规模的增长，数据的获取在成本和时间上变得越来越难以承受，因为大多数直接可用的来源正在被耗尽。此外，隐私、版权和偏见等问题促使该领域超越基于网络的人类生成数据的筛选，转向合成数据生成 [Liang et al., 2022]。

![人类生成公共文本的可用存量与训练 LLM 的数据集规模预测](/figures/figure_19_1.png)
*图 19.1：人类生成公共文本的可用存量与训练 LLM 的数据集规模预测 [Villalobos et al., 2024]。存量线与数据集规模预测线的交点表示存量预计被完全利用的中位年份（2028 年）。*

大语言模型越来越多地自己生成用于训练下一代大语言模型的数据：模型被提示生成指令、对话、推理轨迹（reasoning traces），甚至完整的训练语料库，然后用于微调、蒸馏和评估其他模型 [Long et al., 2024]。这种自我强化的循环降低了数据收集的成本和工作量（与采集和标注人类生成文本相比），同时还提供了对结果数据集的风格、难度和覆盖范围的细粒度控制。到目前为止，这一方法已引起了广泛的工业界 [Kapania et al., 2025] 和学术界 [Viswanathan et al., 2025, Alismail and Lanquillon, 2025] 的关注，涵盖了从通用指令微调到训练智能体行为（如工具使用、规划和多步推理）所需的更专业化数据等应用（如图 1.1 第 17 页所示）。

对模型生成数据日益增长的依赖也在缩放定律（Scaling Laws，第 4 章）中引入了一个新术语，用于解释预训练语料库中合成数据所占的比例。最近的工作如 SYNTHLLM [Qin et al., 2025] 说明了这一点为何重要：通过自动从源文档中提取高层概念，并通过基于图的算法重新组合它们，该方法生成了足够多样的合成语料库，使其在不同模型规模上遵循可预测的、修正后的缩放定律。在这个版本的缩放定律中，收益会更早趋于平缓（在预训练中通常使用的其他 token 预算之前），而且较大的模型相比小型模型在相对更少的 token 上就能达到最优性能。这表明，合成数据不仅可以针对规模进行调优，还可以针对其产生的缩放曲线的形态进行调优。

除了缩放行为之外，为智能体能力——工具使用、规划和多步推理——生成数据越来越依赖于协调的多智能体工作流（multi-agent workflows），而非单一的生成器模型。专业化的智能体可以承担不同的角色（例如，提出任务、执行任务、批评结果），这往往能产生质量更高、更多样化、且在结构上更接近智能体训练实际需求的数据。Matrix [Wang et al., 2025a] 是这一方向的一个例子：一个去中心化框架，其中控制流和数据流都被表示为智能体之间通过分布式队列传递的消息，允许流程在没有中央协调者的情况下水平扩展。

## 19.2 蒸馏循环

在智能体 LLM 训练流程中使用合成数据遵循总体蒸馏循环（Distillation Loop），如图 19.2 所示。一个生成器（一个强模型，或多个智能体的协调系统）使用少量种子数据或真实数据来生成大量原始合成数据。该数据池随后经过*策展*（Curation，第 19.4 节），然后用于训练或*蒸馏*模型。关键在于，生成的模型本身可以成为下一迭代的生成器。这种自我强化循环的闭合给训练稳定性和下游性能带来了相当大的风险（另见第 8 章关于元学习中稳定性的讨论）。

蒸馏是合成数据生成的一种特殊情况，其中生成器是一个*更强模型，其能力正是我们试图转移的*。在知识蒸馏中，一个紧凑的*学生*（student）模型学习复制更强大的*教师*（teacher）模型 [Hinton et al., 2015, Hu et al., 2022]。学生模型可以通过直接优化教师的输出预测来实现，也可以通过简单地训练教师生成的合成数据来实现。蒸馏的目标是获得一个更高效的教师版本——在推理时间和数据成本方面都更高效——同时不过多牺牲任务性能。蒸馏已被广泛应用，包括在智能体场景中 [例如 Li et al., 2025a, Du et al., 2025]。

蒸馏也可用于为指令微调导出偏好数据。例如，Zephyr [Tunstall et al., 2024] 使用 AI 反馈进行训练，其中输出由强大的教师模型生成并排序，以最小的数据和训练成本将小模型与用户意图对齐。

### 蒸馏的四个维度

具体的蒸馏方法可以沿着四个维度来组织。（1）*信号*（Signal）：学生模型是模仿教师的 logits、完整输出序列，还是从教师导出的标量奖励。（2）*数据来源*（Data Source）：被评分的序列是由教师生成的，还是从学生模型中采样的。（3）*时机*（Timing）：数据是一次性预先生成的（离策略，off-policy），还是随着学生模型的变化持续生成的（在策略，on-policy）。（4）*教师身份*（Teacher Identity）：教师是更强的独立模型，还是学生模型自身。下面我们逐一讨论这四个维度。

### 19.2.1 信号：蒸馏目标

当我们能够*白盒*访问教师的概率分布 $q$ 时，学生模型 $p_\theta$ 被训练为使其下一个 token 的分布与教师匹配。在蒸馏中，我们通常使用共享温度参数 $\tau$ 来软化分布（即 $q_\tau(\cdot) \propto \exp(z/\tau)$，其中 $z$ 为 logits）。一个通用的蒸馏损失在语料库上的形式为：

$$\mathcal{L}(\theta) = \mathbb{E}_{x \sim D} \sum_{t} D\left(q_\tau(\cdot|x_{<t}) \| p_\tau^\theta(\cdot|x_{<t})\right) \quad (19.1)$$

其中求和遍历 token 位置 $t$，$D$ 是一个散度（最常见的是 KL 散度），温度 $\tau > 1$ 使两个分布更加平滑，从而使学生模型也能从教师的*相对*置信度中学习。

当仅有教师的*文本*可用时（*黑盒*蒸馏，这是从专有 API 蒸馏时的常见情况），我们不再能观察到 $q$，只能观察到从它那里采样的一些 token。此时软目标 $q_\tau(\cdot|x_{<t})$ 退化为采样 token 上的 one-hot 向量，散度 $D$ 变为 token 级别的交叉熵，公式 19.1 退化为在教师生成数据上的普通监督微调。在第 19.3 节中，我们将讨论 Self-Instruct 技术 [Wang et al., 2023b]。该方法从数据侧进行蒸馏，因此属于黑盒方法。

### 19.2.2 数据来源：教师-学生范式

在蒸馏中，直觉上的假设是更大、更强的教师总是更好。然而，也存在例外 [Xu et al., 2025a, Li et al., 2025b]。一个能力强的教师可能产生的推理轨迹太长、太复杂，或者在风格上与小学生的吸收能力不匹配。这种现象被称为*小模型可学习性差距*（Small Model Learnability Gap）。图 19.3 展示了一种情况：小学生从较弱教师的较短推理中学到的东西，反而比从前沿模型精心设计的思维链中学到的更多。其实际启示是，教师的选择应相对于学生当前的能力来进行，而非孤立地追求最强 [Zhang et al., 2026a]。

![小模型可学习性差距](/figures/figure_19_3.png)
*图 19.3：小模型可学习性差距的可视化。小学生模型并不能持续地从长思维链（CoT）推理中获益，反而在较小的教师产生的较短 CoT 推理上进行微调时表现更好 [Li et al., 2025b]。*

### 19.2.3 时机：离策略蒸馏与在策略蒸馏

第三个维度涉及时机。蒸馏中最常见的方案是*离策略*（off-policy）蒸馏。在这种方法中，我们从教师模型中采样一个固定的完成数据集，然后在这些数据上微调学生模型（如上述黑盒情况）。这是一种简单且可并行化的方法，但它存在训练/推理不匹配的问题。学生模型仅在训练时看到教师生成的 token 序列，但在部署时它必须继续自己*可能存在的缺陷*序列，这些序列可能与训练时看到的不同。这种*曝光偏差*（Exposure Bias）在长智能体轨迹中会不断累积。

*在策略*（on-policy）蒸馏通过从学生模型自身中采样序列并让教师对其进行评分来解决这一问题，所有操作都在循环内完成。广义知识蒸馏（Generalized Knowledge Distillation, GKD）使用教师对这些序列的反馈来训练学生模型在其自生成输出序列上的表现 [Agarwal et al., 2024]。学生模型恰好在其实际访问的状态分布上得到纠正。

这种在策略视角通过模仿学习使蒸馏与强化学习之间的联系变得明确。公式 19.1 中的逐 token 教师散度充当了*密集的、token 级别的奖励*。蒸馏被转化为一种强化学习形式，其中教师——而非稀疏的结果检查器——提供奖励信号 [Lu and Lab, 2025]。混合方案将这一思想进一步推广，在强化学习阶段仅选择性地模仿教师有帮助的部分 [Zhang et al., 2026b]。

### 19.2.4 教师身份：自蒸馏与自我改进

教师模型和学生模型不必不同。当教师和学生模型相同时，蒸馏就变成了自我改进：模型生成候选解，保留通过检查的解，然后在这些解上进行训练。STaR [Zelikman et al., 2022a] 以这种方式引导推理，迭代地生成推理过程，保留那些得到正确答案的推理，并在它们之上进行微调。

另一种方法是自博弈微调（Self-Play Finetuning, SPIN）[Chen et al., 2024]。在该方法中，模型在迭代中区分自己的生成与参考数据，在无需任何外部教师的情况下改善对齐。也许出乎意料的是，即使在没有新数据来源的情况下进行*重复*自蒸馏，也能产生可衡量的提升，直到某个极限 [Pareek et al., 2024]。

当候选输出可以被*廉价验证*时，自我改进最为强大。在这种情况下，外部信号仍然可以被有效地纳入。这在代码和数学问题中就是如此，因为解决方案容易执行和检查。例如，CURE 是一个强化学习框架，其奖励机制从交互结果中共同进化模型的编码和单元测试生成能力。这里没有作为监督的真值代码。由于代码容易执行和检查，编码器和测试编写器充当相互适应的智能体，实现了对困难问题的长期优化。同样的原理也支撑着自我挑战和自我进化的智能体，它们提出自己的越来越困难的任务，并随时间更新其生成策略 [Zhou et al., 2025, Huang et al., 2025, Wang et al., 2025b]。

## 19.3 模拟人类生成内容

从自然产生的人类生成文本（无论是直接获取还是从网络抓取）的转变，或许最好地体现在从人工策划的指令数据向合成生成扮演更核心角色的数据集的演进过程中。我们现在将讨论这些方法，这些方法的核心仍然基于人类生成的数据。

作为人类仍然支撑大部分数据的资源的一个例子，Natural Instructions [Mishra et al., 2022] 包含 61 个不同的任务、其人工编写的指令以及 193k 个任务实例（输入-输出对）。这些指令从现有 NLP 数据集的说明文档中收集，全部映射到统一的模式。LLM 实验表明，模型从同时观察指令和示例中受益，尽管这些模型的表现仍远低于估计的性能上限。

后续工作专注于增加唯一任务和任务类型的数量 [Wang et al., 2022]、变化指令的长度 [Bach et al., 2022]，或包含特别困难的任务 [Srivastava et al., 2023]。重要的是，所有这些元数据集（数据集的数据集）最终仍然建立在人类基准之上：它们包含的每个样本都是由人编写的。因此，可以从网上自由获取的这类数据存在实际上限。

由于这些方法依赖大量以众包数据集形式存在的人类监督，最近的工作专注于生成能填补同样角色的合成数据。在这里，我们看到了诸如 Unnatural Instructions [Honovich et al., 2023] 等数据集的创建，其中包含以极少人力收集的创意性和多样性指令，转而依赖对各种 LLM 的提示。实验表明，在有些嘈杂的 Unnatural Instructions 数据集上训练模型能产生与在高质量、人工策划的数据上训练相当的结果，如图 19.4 所示。这一结果表明，机器生成的数据为扩展和多样化训练数据集提供了一种成本高效的替代方案。

![Unnatural Instructions 与 Super-Natural Instructions 的缩放实验对比](/figures/figure_19_4.png)

生成模型对人类风格文本、代码和推理的模拟，为训练和评估机器学习系统开辟了新的方法论。通过提示强模型，研究人员可以生成高度多样化和复杂的数据集来模拟人类内容生成。例如，PersonaHub [Ge et al., 2025] 使用大规模角色集合来引导生成过程，利用它们提示 LLM 产生比无条件生成更多样化的合成数据。与自我改进类似，在模型输出相对容易验证的领域——如数学 [Yang et al., 2023, Liu et al., 2023]、编程 [Haluptzok et al., 2023] 和游戏 [Wang et al., 2023a]——在合成数据上训练已显示出很大的前景。

### 19.3.1 生成训练数据

我们现在将聚焦于生成训练数据。使用合成数据进行训练已从一个小众的数据增强技术转变为现代模型对齐和推理流程的核心组件。Self-Instruct [Wang et al., 2023b] 等技术已经证明，较小的开放权重模型可以使用完全由更强的专有模型生成的数据进行指令微调。如图 19.5 所示，该过程涉及用少量人类编写的指令来引导 LLM，并提示它迭代地生成新的任务描述、输入和输出。这种模拟的人类内容使模型能够获得复杂的零样本能力，而无需大量人类标注者。

**利用现有数据** 其他方法将策划的人类数据与合成数据相结合，而非用一种替代另一种。Gunasekar et al. [2023] 表明，在人类编写的教科书和合成生成的文本的混合数据上训练，可以产生能力很强的语言模型，这表明策划的人类数据和机器生成的数据是互补的，而非替代关系。一个挑战是，合成生成的数据往往缺乏多样性，并且会继承错误和幻觉，即使它是以人类生成的数据为种子的。后续的改进使用了基于真值文档的生成过程 [Lupidi et al., 2025, Yue et al., 2024]。

![Self-Instruct 流程](/figures/figure_19_5.png)
*图 19.5：Self-Instruct 流程 [Wang et al., 2023b]。*

扩增有限种子集的另一种互补方式是*回译*（Backtranslation）。这种方法最初在机器翻译中被引入，用于通过将句子从源语言翻译到目标语言再翻译回源语言来合成平行数据 [Edunov et al., 2018]。同样的原理可以被重新用于推理任务：不只是为单个问题生成特定的解，而是生成与现有解一致的新问题。MathGenie [Lu et al., 2024] 将这一思想应用于数学推理：取一组问题-解答对作为种子集，增强解答，然后将它们回译为新的问题。由于每个新生成的问题都基于一个经过验证的解答，这种方法在减少错误和幻觉的同时扩展了训练数据的规模和多样性。

**人在回路中的方法** 全自动生成流程并不总是足够的。模型可能难以生成特定场景或领域相关的案例。这些失败的原因通常是生成 LLM 存在特定的盲点，这也使得生成真正有信息量的数据变得困难 [Lippmann et al., 2024]。这类问题促使了*人在回路中*（Human-in-the-Loop）方法的发展，其中人类引导、筛选或修改机器生成的内容，而非从头编写。

WANLI [Liu et al., 2022] 将一个提议具有挑战性的自然语言推理示例的语言模型与过滤并重新标注它们的人类标注者配对，结合了自动生成的可扩展性与人类质量控制。EvalAssist [Santillan Cooper et al., 2025] 将类似原理应用于评估工具，使用合成数据来支持和加速人类判断。

一种相关策略是提示语言模型生成初始种子文本，由人类评分者在结果被用于引导更大的全合成数据集之前进行编辑。通过这种方式，人类的精力花在纠正模型上，而非编写每个示例。

### 19.3.2 生成评估数据

除了训练之外，合成生成在评估中也扮演着关键角色。传统的静态基准面临快速的数据污染问题，即测试集无意中泄露到现代 LLM 的预训练语料库中。为了缓解这一问题，动态评估框架 [Kiela et al., 2021] 越来越依赖合成数据生成来创建定制的一次性测试用例。此外，*LLM-as-a-Judge* 范式 [Zheng et al., 2024] 通过提示强模型对其他模型的输出进行评分来模拟人类评估，与人类偏好高度相关，并显著降低了评估周期的延迟。

为 LLM 创建专门的困难基准也可以再次使用人在回路中的方法，例如 MATH² 基准。该基准使用多个 LLM 通过多轮提示迭代地生成和调整数学问题及解答。然后人类标注者进一步扩展问题并检查答案，在此过程中同样借助 LLM 的辅助 [Shah et al., 2024]。其他高效生成合成评估数据的方法将标注者的任务从创建新样本转变为编辑样本以使其对 LLM 更难 [Yuan et al., 2021]。

**自动化红队测试** 机器生成评估的一个特定用例是通过*自动化红队测试*（Automated Red Teaming）进行面向安全的评估。在这种方法中，一个 LLM 生成对抗性提示，在部署前探测目标模型的漏洞 [Ganguli et al., 2022]。通过合成大量潜在恶意提示，研究人员可以以人类红队无法匹敌的规模对模型进行压力测试并加固其防御，防止有毒输出、越狱和对齐失败 [Perez et al., 2022]。由于相同的生成提示随后可以用于针对这些失败对目标模型进行微调，红队测试处于合成评估和合成训练数据的边界上。

### 19.3.3 生成智能体数据

在智能体场景中，数据必须为整个轨迹（trajectory）进行合成（而非仅为单个指令-响应对）。由于智能体与其环境交互，会产生完整的工具调用、观察和决策序列 [Kang et al., 2025]。这超越了训练或评估在单个输入-输出对上操作的常规 LLM 所需的数据。生成智能体数据比生成用于指导底层 LLM 本身的数据更为复杂，即使通常使用相同的生成模型来产生它。让我们看一个例子。

**示例 2.** 考虑为工具使用智能体合成单个训练轨迹，大致遵循 APIGen-MT [Prabhakar et al., 2025] 的两阶段方案。

首先，一个*任务提议者*（Task Proposer）构思一个合理的用户目标和一组可用工具，以及一个真值答案：*用户：*"这个周末莱顿的天气如何，我需要带伞吗？"*工具：* get_forecast(city, days)。

然后，一个*执行者*（Actor）模型展开交互，发出中间工具调用并消费其（模拟的）观察结果，然后给出答案：

```
get_forecast("Leiden", 2) → {sat: rain, sun: clear} → "周六有雨，周日晴——周六记得带伞。"
```

最后，一个*验证者*（Verifier）检查发出的调用是否格式正确、参数是否与请求匹配、最终答案是否与观察一致。只有通过验证的轨迹才会被保留。请注意需要合成的内容：不仅是单个输入-输出对，还有目标、工具模式、调用、观察，以及验证整个轨迹的检查器。

智能体生成的方法通常涉及多个智能体的完整协调，进行包含人类输入和工具使用的多轮对话 [Wu et al., 2024]。APIGen-MT [Prabhakar et al., 2025] 以两阶段框架 exemplify 了这一转变，生成可验证且多样的多轮智能体数据。TOUCAN [Xu et al., 2025b] 以更大规模追求类似目标，模拟真实的工具调用来构建大型工具智能体数据集。

除了为固定技能生成轨迹之外，一些工作专门合成数据以将新技能或行为从强模型转移到弱模型，这一过程被称为*生成式教学*（Generative Teaching）[Crispino et al., 2024]。此外，智能体合成数据不限于文本，类似的生成流程可扩展到图像、表格数据以及其他形式的交互或行为数据。

对于智能体合成数据的生成，控制任务复杂性是一个反复出现的挑战。例如，深度研究智能体旨在通过与在线工具的长期交互来解决复杂的问答任务，但用于训练它们的典型数据缺乏对难度和质量的细粒度控制，导致合成的数据无法捕获足够的复杂性。Pandit et al. [2025] 通过一个流程解决了这一问题，该流程合成问答对并逐步增加任务复杂性，直到前沿基线 Web 智能体失败。这种课程学习（Curriculum Learning）方法直接根据智能体能力而非固定启发式来校准任务难度。

AReaL-SEA [Gao et al., 2026] 从互补的角度解决可靠性问题。在该方法中，一个多智能体引擎合成基于工具的对话，并结合可执行的逐实例检查器。随后，一个闭环自我进化过程随时间更新提示以提高可靠性。

## 19.4 数据策展

合成数据生成之后，我们需要检查其质量并进行策展（Data Curation）。这通常意味着过滤、评分和选择样本，使只有有用的示例被保留。评估合成数据的有用性可以通过两种互补的方式进行：*外在*评估（Extrinsic Evaluation），通过测量其对下游任务的影响；或*内在*评估（Intrinsic Evaluation），通过直接检查生成数据（或生成过程）的属性。

在实践中，策展被实现为多阶段过滤流程，其中以下将讨论的标准被转化为具体的操作算子。典型的阶段包括*语义去重*（Semantic Deduplication，通过嵌入相似度去除近似重复的示例以保留多样性）、*困惑度过滤*（Perplexity Filtering，使用参考模型丢弃不连贯或偏离分布的文本）、基于规则或格式的检查，以及*奖励模型或评判者评分*（Reward-Model or Judge Scoring）以仅保留高保真样本。开创性的 *Textbooks Are All You Need* 论文 [Gunasekar et al., 2023] 提醒我们，策展步骤的重要性往往不亚于数据量：对质量的严格过滤可以超过单纯的数量。如果没有策展，模型会轻易地学习其教师的生成伪影和统计异常。

### 19.4.1 外在评估

外在评估回答一个简单的问题：合成数据是否真的对下游任务有帮助？这一主题也被称为*效用*（Utility）。在实践中，效用通过在合成数据上训练或微调模型（单独或与真实数据混合），并在保留的真实世界测试集上进行评估来衡量。

外在评估是衡量合成数据是否有用的最直接方式。例如，如果预训练模型在包含合成数据时的性能（例如以困惑度衡量）有所提升，我们可以得出结论：数据是有用的。然而，它也是最昂贵的：在获得任何信号之前需要完整的训练运行。如果我们对生成过程进行修改或选择不同的数据集，就需要重新训练和评估模型。这使得外在评估不适合在生成过程中过滤或选择单个示例。

### 19.4.2 内在评估

内在评估则关注生成内容本身的特征，无需承担下游训练运行的成本。已有若干质量维度被提出用于评估合成文本 [Ramesh et al., 2025]。除了在输出层面进行评估之外，也可以直接对生成过程的语言模型进行基准测试 [Kim et al., 2025b]。这可以提供比检查生成数据更早、更低成本的信号。

**数据正确性** 一个生成的示例只有在其内容在事实和逻辑上都合理时才有用。由于合成数据通常来自其他 LLM，它继承了生成模型的失败模式，包括幻觉事实、不一致的推理，或与内容不匹配的标签。这些错误随后可能传播到在其上训练的模型中。正确性通常通过与人类生成的标签进行比较 [Long et al., 2024, Chim et al., 2025]、执行验证（例如基于规则的检查器或独立的评判模型）[Chen et al., 2025a, Yang et al., 2025, Setlur et al., 2024]，或通过对同一输入的多次生成进行一致性检查来评估 [Zelikman et al., 2022b, Seegmiller et al., 2025]。

**数据多样性** 创建合成数据的一个关键问题是维持多样性。Logit 抑制和温度采样可以提高数据多样性，但以数据正确性为代价 [Chung et al., 2023]。多样性也难以衡量：词汇启发式方法（如 ROUGE）或神经启发式方法（基于嵌入的相似度）常被用作代理指标，但每种方法只能捕获数据中可能变异的一部分。MetaSynth 通过元提示（Meta-Prompting）生成增强多样性的合成数据来解决这一问题，其中语言模型协调多个专家 LLM 智能体协作生成数据 [Riaz et al., 2025]。

**数据污染** 合成数据面临的一个严重风险是污染（Data Contamination）[Deng et al., 2024, Balloccu et al., 2024]。生成 LLM 在大规模的、过滤不完全的网络数据集上进行预训练，可能记住了基准测试数据，并在被提示生成新的训练示例时复现或接近复述它们。经过多步之后，合成生成的数据会收敛到现有基准测试的内容。这会人为地膨胀评估分数，例如在代码生成基准测试中 [Matton et al., 2024]。这类泄露的解决方案应超越简单的精确匹配过滤，需要对已知基准进行 n-gram 重叠搜索、成员推断风格的探测 [Puerto et al., 2025, Huang et al., 2026]，或动态数据集构建流程 [Chen et al., 2025b]。

**公平性与偏见** LLM 从其自身训练数据中继承并放大社会偏见。如果我们反过来使用 LLM 生成合成语料库，我们就冒着进一步延续刻板印象关联、扭曲的人口统计表征，或在不同社会群体间产生不平等生成质量的风险 [Gallegos et al., 2024]。这对合成数据而言尤为令人担忧，因为它以大规模生产，且通常直接作为新 LLM 的训练材料被消费。

最后，内在指标只是有用性的代理。一个数据集可能在多样性上得分良好或通过正确性检查，但未能改善甚至损害外在评估。词汇和神经多样性启发式方法衡量的是表面层面的变异，可能无法发现以重要方式存在的冗余（例如重复的推理模式），或高估多样性。正确性检查还依赖于可信参考、基于规则的验证器或评判模型的存在，对于开放式或主观性生成，这可能不存在或不可靠。因此，内在评估最好被视为额外的检查手段，而非外在评估的真正替代。

## 19.5 风险

到现在应该已经清楚，使用合成数据训练智能体 LLM 并非没有问题。我们将讨论与合成数据相关的几个更多风险，包括模型崩溃、偏见放大、安全与隐私漏洞，以及法律和伦理问题。

### 19.5.1 模型崩溃

图 19.2 中循环的固有风险在于它以自身输出为食。*模型崩溃*（Model Collapse）是一个被充分记录的现象：在递归生成的 AI 数据上训练连续的模型代际，会导致原始分布的多样性消失 [Shumailov et al., 2024]。稀有事件和低概率的语言细微差别被越来越少地采样，因此每一代都会更多地遗忘分布的长尾行为，直到模型收敛为一个重复的、高概率的模型。一些实验表明，在纯合成数据上重复训练会产生递减并最终为负的回报 [Singh et al., 2024]，而将语料库集中在少数几个合成来源（而非多个）上会增加所得模型的脆弱性 [Schaffelder and Gatt, 2025]。类似地，从教师蒸馏的小模型容易产生幻觉，并且在长尾知识上常常表现不佳 [Kandpal et al., 2023]。

更微妙的是，模仿教师可能产生一个匹配教师*风格*但在*事实性*上落后的学生模型，这种差距通常只有通过针对性的能力基准测试才能揭示 [Gudibande et al., 2023]。标准的缓解措施是持续用真实人类数据来锚定语料库，而非仅依赖合成数据进行训练。

### 19.5.2 偏见放大

由于生成模型过度表征其训练分布的多数模式，合成数据往往会截断自然人类话语中存在的多样化、长尾视角 [van der Meer et al., 2024]。在这种数据上训练的学生模型因此可能展现出教师社会偏见的放大版、漫画化的版本。学生模型复现刻板印象关联、扭曲的人口统计表征，或在不同群体间不平等的生成质量 [Gallegos et al., 2024]。对于合成数据而言，这一担忧比对原始模型输出更大，因为数据以大规模生产并直接作为训练材料消费，且循环的每一轮都会叠加前一轮的影响。

### 19.5.3 安全风险

合成训练数据也带来安全风险。依赖生成数据引入了恶意污染训练数据的新攻击向量。如果教师模型或生成流程的任何阶段被攻破，攻击者可以发起数据投毒攻击。由于合成语料库通常太大而无法全面审计，微妙的后门或恶意的指令-响应对可能被插入，在部署的学生模型中被触发前保持休眠状态。即使在网络规模语料库中投毒极小比例也被证明是可行且低成本的 [Carlini et al., 2024]，而当"教师"是一个不受控制的第三方模型——其训练数据和对齐方式不透明——时，风险更为突出。

### 19.5.4 隐私保护

合成生成经常被提及为数据隐私的解决方案。其思想是合成数据不包含个人身份信息（PII）[Dwork and Roth, 2014]，同时能够反映私有数据的统计特性（如医疗记录）。然而，在这类数据中存在实质性的记忆风险。如果在生成阶段没有严格的隐私保障，生成模型可能无意中重建并因此泄露其最初训练所基于的敏感人类数据的确切片段 [Carlini et al., 2021]。隐私评估表明，现成的隐私保护方法可能会失败 [Ramesh et al., 2024]。

常见的隐私方法依赖差分隐私（Differential Privacy）[Dwork et al., 2006]，这是对生成过程的一种保障，限制当单个个体的记录被添加到数据集中或从数据集中移除时，输出分布可能发生的变化程度。这个界限由隐私预算（Privacy Budget）控制，较小的值强制执行更强的保护，但以更大的效用损失为代价 [Yue et al., 2023]。

### 19.5.5 版权与使用条款

合成数据的吸引力之一是它绕过了抓取互联网规模人类文本的法律地位不明确的问题——这已经引发了版权诉讼。2025 年美国的 *Bartz v. Anthropic* 和解案具有说明性。地区法院发现 LLM 训练本身*极其*具有变革性，因此是合理使用的候选，但责任仍然源于底层语料库的*获取方式*——即摄入了数十万本盗版书籍——Anthropic 以每部作品约 3,000 美元（总计约 15 亿美元）达成和解，与 *Kadrey v. Meta* 等其他法律案件有相似之处。这表明，训练所用数据的版权和使用条款正受到越来越严格的审查。

合成数据并不能完全摆脱这一问题。从专有模型蒸馏引发了一个独特的问题：大多数商业 LLM API 的服务条款明确禁止使用其输出来训练竞争模型。因此，由黑盒教师生成的数据无论版权如何都可能在法律上存在问题。这种紧张关系在 2025 年公开浮现，当时有指控称竞争系统是在前沿 API 的输出上训练的。对于从业者而言，这意味着*生成器*的许可证与其替代的任何人类数据的许可证同样重要检查。

## 19.6 总结

合成数据已从一个小众的增强方法转变为 LLM 流程的核心组成部分（第 3 章），其驱动力是人类文本可能成为扩展瓶颈的前景（第 4 章）。强模型和多智能体协调系统可以模拟指令数据、评估基准，以及最近出现的完整的智能体*轨迹*——包括工具调用和决策（第 9 章和第 11 章）。由于原始生成内容存在噪声，策展——外在效用以及对正确性、多样性和污染的内在检查——与生成本身同等重要。

各种设置可以被视为沿着信号、数据来源、时机（离策略与在策略）和教师身份四个维度组织的知识蒸馏形式。将来自同一模型的合成数据用于自我改进，为实现可验证推理提供了前景（第 6 章）。然而，在所有这些流程中，我们需要谨慎对待这些模型消费的数据：如果没有真实数据的锚定和仔细的审计，模型崩溃、偏见放大、安全、隐私和许可风险都会在每次迭代中不断累积。
