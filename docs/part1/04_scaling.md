# 缩放定律与高效大语言模型

##### ‡学习目标

在本章中，你将学习语言模型的性能如何随数据和训练量的增加而扩展。具体而言，你将能够：
- 解释模型性能如何通过*缩放定律（Scaling Laws）*与计算量、数据量和模型规模相关联，并预测在固定其他因素时增加某一因素的效果。
- 描述可用于开发*更小的语言模型（Smaller Language Models）*的技术，并分析使用更小模型在计算需求和性能方面的权衡。
- 识别*推理时计算（Inference-Time Compute）*与训练时计算之间的区别。
- 反思*可持续语言模型（Sustainable Language Models）*以及大规模部署带来的环境与隐私影响。

## 4.1 缩放定律：计算量、数据量、参数量

训练大语言模型（LLM）涉及三个主要因素：(1) 计算量，(2) 数据集规模，(3) 模型规模。研究表明，这三个因素与模型的最终性能（以在留出测试集上的损失 $L$ 来衡量）之间存在关系。这种关系被发现是平滑且可预测的。其形式为*幂律（Power Law）*：当三个资源中的任何一个增加时，损失按该资源的负幂次比例下降。例如，将模型规模加倍可能使损失降低 $2^{-\alpha}$ 倍，其中 $\alpha$ 为某个正指数。由于行为是可预测的，我们可以在承诺进行昂贵的训练运行*之前*，估计模型将改善多少（例如，通过将训练数据集规模加倍）。

![图 4.1 语言建模目标的损失是训练计算量、数据集规模和模型规模的函数 [Kaplan et al., 2020]](/figures/figure_4.1.png)

我们定义这三个量（$C$, $D$, $N$）如下：

- **计算量（$C$）**：整个训练过程中执行的算术运算总量，以浮点运算次数（FLOPs）衡量。请注意，这是运算的总计数，而非每秒的速率。一个广泛使用的近似将其与另外两个量关联为 $C \approx 6ND$，因为处理单个 token 大约会触及 $N$ 个参数六次——前向传播两次，反向传播四次。

- **数据集规模（$D$）**：模型训练所用的 token 总数。请注意，token 是由分词器定义的子词单元，因此同一语料库在不同分词器下对应不同的 $D$ 值。$D$ 的计数是训练运行中使用的 token 数量。当数据在多个 epoch 中重复时，重复的 token 仍然计入 $D$，但与新鲜数据相比可能收益递减。

- **模型规模（$N$）**：模型架构中可训练参数（权重）的数量。该计数通常仅指随模型深度增加而增长的参数，因此不包括嵌入矩阵。

训练大型模型的成本相当可观，通常高达数千万美元，计算时间可达数月。缩放定律使我们能够预测模型是否能训练良好。

### 4.1.1 Kaplan 缩放定律

关于缩放定律有不同的经验结果，这些结果是通过对经验测试数据拟合函数而得到的。例如，在图 4.1 中，每个点都是在固定数据集上使用相似实验设置训练的模型，仅改变三个主要变量 $C, D, N$。2020 年初，Kaplan 等人 [2020] 发现了模型性能与 $C, D, N$ 之间的关系。他们根据经验观察估计，损失遵循与三个主要变量相关的独立幂律：

$$L(N) \propto N^{-\alpha_N}$$

$$L(D) \propto D^{-\alpha_D}$$

其中 $\alpha_N \approx 0.076$，$\alpha_D \approx 0.095$。各个幂律可以合并为一个可优化的方程，如公式 4.1 所示。这种关系被认为是通用的：它同样适用于"其他生成式建模任务"的模型损失行为 [Kaplan et al., 2020, p. 5]。作者进一步表明，在仅有计算预算约束的条件下，他们的推导将指向最优模型规模 $N$、理想数据集规模 $D$，由最优步长（$S$）和批量大小（$B$）定义。

$$L(N, D) = \left(\frac{N_c}{N}\right)^{\alpha_N} + \left(\frac{D_c}{D}\right)^{\alpha_D} \quad (4.1)$$

具体而言，他们得出结论：随着计算预算 $C$ 的增加，模型规模 $N$ 应比数据规模 $D$ 增长得更快（$N \propto C^{0.73}$，$D \propto C^{0.27}$），这导致了 GPT-3 等大型模型的开发。负指数反映了收益递减：模型规模或数据集规模每翻一番，损失仅降低几个百分点。乍一看，这一建议似乎与指数本身相矛盾：由于 $\alpha_D > \alpha_N$，对于相同的计算相对增量，数据缩放比参数缩放*更快*地降低损失。原因在于约束条件是计算量而非资源本身：因为 $C \approx 6ND$，增加 $D$ 与增加 $N$ 消耗的计算量相同。这意味着 $N$  Increasing 时越来越可能成为瓶颈。因此，一旦考虑了 $D$ 的计算成本，将额外计算量分配给 $N$ 比分配给 $D$ 的回报更好。这意味着最优分配倾向于更大的模型。

**样本效率（Sample Efficiency）** Kaplan 等人 [2020] 的另一个独立观察是，更大的模型具有更高的*样本效率*。对于固定数量的训练 token，更大的模型能达到更低的损失，并且要达到给定的目标损失，它比更小的模型需要更少的 token 和更少的优化步数。这一效应在图 4.2 中可视化。

![图 4.2 更大的模型使用更少的训练 token 达到给定损失，展示了更高的样本效率 [Kaplan et al., 2020]](/figures/figure_4.2.png)

$$\frac{1}{B} \propto C^{0.24}, \quad S \propto C^{0.03}, \quad D = B \cdot S \propto C^{0.27} \quad (4.2)$$

### 4.1.2 Chinchilla 缩放定律

2022 年，Hoffmann 等人 [2022] 使用名为 Chinchilla 的模型重新评估了这些发现，并令人惊讶地发现，当时的大多数大型模型都严重训练不足。这一差异可以追溯到 Kaplan 等人 [2020] 的方法论：他们的最优分配是从许多模型*早期*的、未收敛的训练动态中外推得出的，而非从训练至收敛的运行中得出的，这系统性地使他们的结论偏向于训练步数更少的大型模型。

Chinchilla 研究的关键洞察是：计算预算每翻一番，模型规模 $N$ 和训练 token 数量 $D$ 应大致按等比例增加（$N \propto C^{0.5}$，$D \propto C^{0.5}$）。他们的经验法则建议：对于模型中的每个可训练参数，大约使用 20 个 token 进行训练以达到计算最优性。这一结果此后已被复现 [Besiroglu et al., 2024]，并被证明对相当大的扰动具有鲁棒性 [Schaeffer et al., 2025]。

在他们的缩放定律中，损失被建模为参数量 $N$ 和训练 token 数 $D$ 的函数，如下所示：

$$L(N, D) = E + \frac{A}{N^\alpha} + \frac{B}{D^\beta} \quad (4.3)$$

第一项 $E$ 捕获不可约损失，对应于自然文本的熵。第二项 $\frac{A}{N^\alpha}$ 捕获有限参数 $N$ 的次优性，最后一项 $\frac{B}{D^\beta}$ 捕获在有限 token 数 $D$ 上训练的次优性。虽然这里的 $\alpha$ 和 $\beta$ 与 Kaplan 的 $\alpha_N$ 和 $\alpha_D$ 扮演相同的角色（控制损失随模型规模和数据下降的指数），但它们是不同的参数化：它们在这个两项形式中联合拟合，因此取不同的值。在超过 400 个模型上拟合 Chinchilla 缩放函数，得到以下参数估计：

$$E \approx 1.69, \quad A \approx 406.4, \quad B \approx 410.7, \quad \alpha \approx 0.34, \quad \beta \approx 0.28 \quad (4.4)$$

通过在固定计算预算 $C$（回忆 $C \approx 6ND$）的约束下优化此损失函数，我们可以推导出对于任意预算 $C$ 的计算最优模型规模 $N_{opt}$ 和数据规模 $D_{opt}$：

$$N_{opt}(C) = G \left(\frac{C}{6}\right)^a, \quad D_{opt}(C) = \frac{1}{G}\left(\frac{C}{6}\right)^b \quad (4.5)$$

其中 $G = \left(\frac{\alpha A}{\beta B}\right)^{\frac{1}{\alpha+\beta}}$ 是常数，$a = \frac{\beta}{\alpha+\beta} \approx 0.45$，$b = \frac{\alpha}{\alpha+\beta} \approx 0.55$。请注意，$a$ 和 $b$ 不是独立的：根据构造 $a + b = 1$。这直接来自 $C \approx 6ND$，因为取对数得到 $\log C = \log 6 + \log N + \log D$。将 $N_{opt} \propto C^a$ 和 $D_{opt} \propto C^b$ 代入，得到 $\log C = \text{const} + a \log C + b \log C$，这只有当 $a + b = 1$ 时才能对所有 $C$ 成立。同样的约束也适用于 Kaplan 的指数（$0.73 + 0.27 = 1$）。Chinchilla 的区别在于预算*如何*在 $N$ 和 $D$ 之间分配。这一规则大致是*线性*的，因为 $N_{opt}$ 和 $D_{opt}$ 以几乎相同的速率随计算预算 $C$ 增长：它们的指数 $a \approx 0.45$ 和 $b \approx 0.55$ 相近，因此比值 $D_{opt}/N_{opt}$ 在计算的许多数量级上保持在大约 20 的常数值附近。该值最好被理解为锚定在真实计算最优运行上的经验校准，而非从拟合系数中干净地产生的数字。Chinchilla 模型本身（700 亿参数，在 1.4 万亿 token 上训练）恰好位于 $D/N = 20$。表 4.1 展示了几个知名模型相对于此规则的位置。低于该比值的模型属于*训练不足*（相对于其 token 预算而言模型过大），而远高于该比值的模型则是有意*过度训练*的，以获得一个在推理时运行成本更低的小模型。早期的旗舰模型如 GPT-3 和 Gopher 远低于该线（$D/N \approx 1\text{--}2$）：它们被做得非常大，但在相对较少的 token 上训练。

| GPT-3 [Brown et al., 2020] | 175B | 300B | ≈1.7 | 训练不足 |

*表 4.1：Chinchilla 经验法则 $D \approx 20N$。几个知名模型的 token 与参数比值。*

值得强调的是，$D \approx 20N$ 仅在固定训练预算下最小化*训练*损失时是最优的。当一个模型后续需要服务大量推理请求时，通常会故意在远多于每参数 20 个 token 的数据上进行*过度训练*，以额外的训练成本换取一个更小的、推理时运行成本更低的模型。例如，LLaMA-3 8B 在大约每参数 1900 个 token 上训练。这种刻意的极端过度训练使得小模型仍能达到低损失，且在推理时运行成本低廉。

到目前为止的情况相当清晰：测试损失随计算量、数据量和参数量平滑、单调且可预测地下降。然而在实践中，各种因素会影响我们的结果。我们讨论四种现象，它们各自探测这一图景的不同边缘：(1) 计算最优曲线，(2) 涌现能力，(3) 逆缩放，(4) 顿悟（grokking）。

### 4.1.3 计算最优曲线

计算机硬件和能源是有限资源。一个实际的问题是：如何在模型规模 $N$ 和数据集规模 $D$ 之间分配固定的计算预算 $C$，以获得尽可能好的模型。缩放定律通过*计算最优前沿（Compute-Optimal Frontier）*来回答这个问题：即最小化损失的 $C$ 的分配方式。这一前沿通过 *IsoFLOP 方法* [Hoffmann et al., 2022] 经验性地定位，如图 4.3 所示。对于各种模型规模，我们选择训练 token 数量使得最终 FLOPs 为常数。学习率使用余弦退火调度进行调整，余弦周期长度设置为匹配目标 FLOP 计数。我们发现损失中存在一个明显的谷底，这意味着对于给定的 FLOP 预算，存在一个最优的模型规模进行训练（左图）。利用这些谷底的位置，我们投影出更大模型的最优模型规模和 token 数量（中图和右图）。以绿色显示的是使用 Gopher 的计算预算训练的最优模型的估计参数量和 token 量。

![图 4.3 IsoFLOP 曲线 [Hoffmann et al., 2022]](/figures/figure_4.3.png)

对于固定的 FLOP 预算，我们训练多个不同规模的模型：太小的模型欠拟合，太大的模型被迫在太少的 token 上训练，因此损失相对于模型规模的曲线呈 U 形。其最小值确定了计算最优模型规模 $N_{opt}$，由此通过 $C \approx 6ND$ 得到匹配的 token 计数 $D_{opt} = C / 6N_{opt}$。对每条这样的曲线拟合抛物线可以定位最小值，在不同预算上重复此过程可以找到 $N_{opt}$ 和 $D_{opt}$ 如何随计算量增长。这种抛物线拟合必须谨慎进行，这种简化会在估计的最优值中引入系统性偏差 [Czech et al., 2026]。这些偏差即使在无噪声的合成数据上也存在，源于三个来源：(1) 采样的模型规模间距过粗，(2) 采样未能对称地定位真实最小值，(3) 损失面的真实不对称性，对称的抛物线无法表示。在 Llama-3 的规模上，他们估计此类偏差浪费了约 140 万美元的计算量。作为补救措施，他们建议直接拟合参数化损失模型 $L(N, D) = E + A/N^\alpha + B/D^\beta$——即 Chinchilla 方法 3，与我们上面用来推导 $D \approx 20N$ 规则的形式相同——使用数值鲁棒的优化器，而非从拟合的抛物线上读取最优值。

互补的缩放视角 [Paquette et al., 2024] 研究的是解析可解模型（用单遍随机梯度下降训练的幂律随机特征），而非对训练后的模型拟合曲线。他们发现计算最优指数不是单一的通用常数，而是数据复杂度/目标复杂度平面分裂为四个主要阶段（加上三个子阶段），每个阶段有自己的指数控制 $N_{opt}$ 如何随计算量增长。对于应该应用哪种分配规则的问题，以及固定的*每参数 20 个 token*是否甚至是正确的形状，答案取决于问题的机制。

**微调的缩放（Scaling for Finetuning）** 前述工作研究了预训练如何缩放。这些缩放定律是否也支配微调？Zhang 等人 [2024] 研究了全模型微调（更新模型的所有权重）和参数高效微调（PEFT）（冻结预训练权重，仅训练一小部分新增参数，如 LoRA）[Hu et al., 2021] 的这个问题。与计算预算最相关的经验是：微调性能的提高更多来自扩大*基础模型*的规模，而非收集额外的微调数据，同时增加更多可训练的 PEFT 参数帮助不大。在实践中，对于表现不佳的任务，通常从更大的预训练模型开始比扩大适配器或收集更多微调样本更有效。

### 4.1.4 涌现能力

大语言模型缩放中最有趣的一些现象是*涌现能力（Emergent Abilities）*：在较小模型中不存在、但当模型规模或计算量跨越某个阈值时突然出现的能力 [Wei et al., 2022]。示例包括多步推理、少样本翻译和专门的编码任务，如图 4.4 所示。当语言模型在达到一定规模之前通过少样本提示执行某项任务仅达到随机水平的性能，之后性能显著提升远超随机水平时，该能力即为涌现的。

![图 4.4 少样本提示设置中涌现的八个示例，每个点是一个独立的模型 [Wei et al., 2022]](/figures/figure_4.4.png)

然而，这种突然性受到了质疑。Schaeffer 等人 [2023] 认为，涌现能力可能是由评估指标的选择造成的假象。例如，在图 4.5 中，我们看到虽然非平滑的离散指标（如准确率或精确匹配）显示出急剧跳跃——毕竟它们是非平滑的——但底层指标（如交叉熵损失或 token 级概率）遵循平滑的、可预测的跨规模幂律。

![图 4.5 将指标从非线性（上）改为平滑（下）指标后，声称的涌现能力消失了 [Schaeffer et al., 2023]](/figures/figure_4.5.png)

### 4.1.5 逆缩放

虽然大多数任务随规模改善，但有些任务表现出*逆缩放（Inverse Scaling）*，即更大的模型表现更差或发展出更强的偏见。这可能发生在这样的任务中：根据语言建模目标，一个干扰性答案比正确答案具有更高的概率，导致更大（且更自信的）模型一致地选择错误选项 [McKenzie et al., 2023, Michaelov and Bergen, 2023]。

逆缩放的一个例子是*后见之明忽视（Hindsight Neglect）*，这是一项测试基于期望值来判断下注是否值得的任务。如果期望值为正，模型应回答*是*；如果期望值为负，模型应回答*否*。具体情况如下：模型只看到少样本示例，其中实际结果始终与期望值匹配（即，当期望值为正时下注者赢了钱，当期望值为负时输了钱）。然后向模型提出一个问题：对于期望值与实际结果不匹配的情况，下注是否正确。后见之明忽视测试的是模型能否在少样本示例标注正确但具有误导性的情况下，从指令中正确泛化。*重复代数（Repetitive Algebra）*测试的是当给定特定模式的正确标注少样本示例时，模型如何回应简单的代数问题。图 4.6 显示，模型通常从大约随机性能开始，但在约 $10^{22}$ 训练 FLOPs 时降至随机性能以下。

### 4.1.6 顿悟（Grokking）

顿悟（Grokking）是统计学习理论中一个相对较新的悖论。该理论认为，通常情况下，当一个大模型面对一个小数据集时，由于对示例的记忆，它会过拟合。而顿悟发生在我们继续训练这个过大模型时——经过更多的训练后，模型突然找到了一个泛化解 [Power et al., 2022]。虽然最初是在小型算法任务（如模加法）上观察到的，但顿悟现象表明，增加训练步数（过度训练）可以导致从记忆到理解的质性转变，即使不增加数据集规模 $D$，见图 4.7。该图显示了一个数据墙（data wall），最初由于数据耗尽而限制了缩放 [Villalobos et al., 2024]，但后来经过更多训练后，模型顿悟了一个泛化解。

![图 4.7 模块化加法任务上的早期训练集记忆（蓝色）与后期泛化（红色：顿悟）[Nanda et al., 2023]](/figures/figure_4.7.png)

顿悟与语言建模相关，因为我们正在迅速耗尽互联网上高质量的人类文本，以满足 Chinchilla 缩放对下一代模型数据 $D$ 的要求。由于这些固有限制，研究人员正在超越 $D$ 的简单缩放。作为替代，我们可以关注这些新前沿的多个方向：(1) 更好的架构效率（如混合专家模型），(2) 推理时缩放（如在推理时给予模型更多计算量来*思考*，如 OpenAI 的 o 系列所示），或 (3) 合成数据生成（第 19 章）。

## 4.2 小语言模型

随着计算和数据需求的持续增长，人们对*小语言模型（Small Language Models, SLMs）*的兴趣日益增加：这些模型足够小，可以在消费级硬件甚至移动或边缘设备上运行，同时保持高性能。这些模型通常使用优化效率而不牺牲太多性能的技术来开发。为了理解这些模型的部署格局，对常见的计算基础设施类型进行分类是有帮助的：

- **数据中心**：高性能 GPU（如 NVIDIA H100）和 TPU，主要用于*预训练*大型模型和承载高吞吐量推理 API。

- **消费级硬件**：标准桌面 GPU 和高端 CPU，小语言模型可以在这里被经济实惠地*微调*或由个人用户在本地运行。

- **边缘设备**：手机、物联网设备和笔记本电脑，越来越多地配备了专门设计用于低功耗、高效设备端*推理*的神经处理单元（NPU）。

为了使模型适应后者的受限环境，优化技术聚焦于加速吞吐量、降低延迟、减少内存使用和提高样本效率。实现这些目标的技术可以分为两类：(1) 以模型为中心的优化，针对模型的架构及其优化方法；(2) 以数据为中心的优化，针对用于训练模型的数据。我们将讨论这两类技术。

### 4.2.1 以模型为中心的优化

首先我们讨论以模型为中心的优化技术。我们介绍以下技术，这些技术允许高效训练更小的模型，同时仍然保持高任务性能。以模型为中心的技术可以聚焦于预训练/微调或推理。

#### 4.2.1.1 降低预训练成本

**参数高效微调（PEFT）** 诸如*低秩自适应（Low-Rank Adaptation, LoRA）*[Hu et al., 2021] 等方法允许通过仅训练模型参数的一小部分（通常 $<1\%$）来将大模型适配到新任务 [Lialin et al., 2023]。关键观察是，微调期间学到的权重更新具有低*内在秩*：虽然预训练权重矩阵 $W_0 \in \mathbb{R}^{d \times k}$ 是满秩的，但适配到新任务所需的变更 $\Delta W$ 可以很好地用低秩矩阵近似。LoRA 不是直接更新 $W_0$，而是冻结它并将更新表示为两个小矩阵的乘积：

$$W = W_0 + \Delta W = W_0 + BA, \quad B \in \mathbb{R}^{d \times r}, \quad A \in \mathbb{R}^{r \times k} \quad (4.6)$$

其中秩 $r \ll \min(d, k)$。对于输入 $x$，修改后的前向传播变为：

$$h = W_0 x + \frac{\alpha}{r} BAx \quad (4.7)$$

其中 $\alpha$ 是一个常数缩放因子，控制更新的大小，大致类似于标准训练中的学习率。这在图 4.8 中可视化。我们仅对 $A$ 和 $B$ 计算权重更新，将可训练参数的数量从 $d \times k$ 减少到 $r(d + k)$。在初始化时，$A$ 从随机高斯分布中抽取，$B$ 设为零，因此 $\Delta W = 0$，训练从预训练模型开始。由于 $\Delta W$ 在训练后可以直接合并回 $W_0$，LoRA 不增加推理延迟，单个基础模型可以搭配许多小型、可互换的任务特定适配器进行服务。

![图 4.8 低秩自适应重参数化 [Hu et al., 2021]。在微调期间，仅训练 $A$ 和 $B$。](/figures/figure_4.8.png)

**架构创新** 第二类技术直接改变模型架构，使其运行成本更低，而非事后压缩固定架构。两个有影响力的例子是分组查询注意力和混合专家模型。

*分组查询注意力（Grouped-Query Attention, GQA）*[Ainslie et al., 2023] 针对自回归解码的内存带宽瓶颈。在标准的*多头注意力（Multi-Head Attention, MHA）*中，每个查询头都有自己的键和值矩阵，我们都需要使用它们来计算注意力分数。在另一个极端，*多查询注意力（Multi-Query Attention, MQA）*让所有查询头共享单个键/值头，这缩小了计算量但可能损害表达质量和训练稳定性。GQA 在这两者之间插值：查询头被分为 $g$ 组，组内的所有头共享一个键/值头。当 $g = 1$ 时等价于 MQA，当 $g$ 等于头数时等价于 MHA，因此 $g$ 在质量与内存使用之间权衡。通常，GQA 与下面第 4.2.1.2 节讨论的 KV 缓存优化相结合，它现在是许多开放权重模型中的默认注意力变体。

*混合专家模型（Mixture of Experts, MoE）*[Shazeer et al., 2017] 将总参数量与每个 token 花费的计算量解耦。MoE 层不是在每一层中使用单个密集的前馈块，而是包含多个并行的"专家"子网络，以及一个轻量级的*门控网络（路由器）*，为每个 token 仅激活少量专家（通常为 top-1 或 top-2）。因为只有被选中的专家执行计算，所以每个 token 的成本保持在接近单个密集块的水平，即使总参数量（因此模型的整体容量）增长了一个数量级或更多 [Fedus et al., 2022]。这种*稀疏激活*解释了为什么像 Mixtral 和许多最新前沿系统这样的模型可以拥有数千亿总参数，而每个 token 仅激活其中一小部分。权衡在于：(1) 所有专家仍必须保存在内存中；(2) 负载必须在专家之间平衡（通常通过辅助损失），使没有专家被过度或不足使用；(3) 路由引入了额外的工程复杂性。MoE 架构在图 4.9 中可视化，展示了一个 top-$k$ 路由机制，配置为 $k = 2$，其中门控函数基于路由器为每个 token 选择得分最高的两个 FFN 专家。被选中的专家并行评估，其输出通过加权求和进行聚合 [Zhang et al., 2025]。

![图 4.9 在仅解码器 Transformer 之上的稀疏门控混合专家（MoE）架构示意图 [Zhang et al., 2025]](/figures/figure_4.9.png)

**知识蒸馏（Knowledge Distillation）** 使用大型教师模型来训练较小的学生模型，鼓励学生匹配教师的输出分布 [Gu et al., 2023, Xu et al., 2024]。关键在于，学生从教师的完整*软*概率（通常用温度软化）中学习，而非仅从唯一正确答案中学习。这些软目标携带更丰富的信息：例如，教师认为哪些错误答案是合理的。这使得学生能以一小部分的规模接近教师的质量。同样的思想支撑了下面讨论的合成数据生成，其中前沿模型有效地充当教师，为较小的学生模型生成高质量的训练数据。

#### 4.2.1.2 降低推理成本

一旦模型训练完成，可以进一步优化以在推理时部署。训练时技术聚焦于降低生产模型的成本，而推理时技术针对的是*使用*模型的成本：吞吐量（每秒生成的 token 数）、延迟（到第一个 token 和每个后续 token 的时间）以及服务请求所需的内存占用。我们讨论几种常用于降低推理成本的技术，这些技术可应用于大型和小型模型。

**键值（KV）缓存** 在自回归生成过程中，模型一次生成一个 token，每个新 token 关注所有先前的 token。在每一步重新计算整个上下文的注意力键和值的计算复杂度是二次方的。然而，当我们预测新 token 时，上下文保持不变。与其重新计算注意力值，不如将过去 token 的键和值向量存储在 *KV 缓存*中并重复使用。这将每步注意力转变为线性成本的查找。这是使解码变得实用的基本优化，但它也有代价：缓存随序列长度和批量大小线性增长，对于长上下文很快主导内存使用。这个问题推动了上述架构选择（GQA 和 MQA 通过在查询头之间共享键/值头来缩小缓存）以及专用内存管理方案，如 *PagedAttention*，它以非连续块存储缓存以减少碎片化并实现更高的服务吞吐量 [Kwon et al., 2023]。

**剪枝（Pruning）** 一种更激进的减小模型规模的方法是考虑移除神经网络中冗余或不太重要的连接 [Ma et al., 2023]。剪枝可以是*非结构化的*（将单个权重归零）或*结构化的*（移除整个神经元、注意力头或层）；后者在标准硬件上产生具体的加速，而前者需要稀疏感知的内核才能发挥其优势。

**量化（Quantization）** 另一种在推理时节省内存的方法是减小需要加载到内存中的矩阵的大小。与其使矩阵维度更小，我们也可以降低权重条目的精度（例如，从 16 位到 8 位或 4 位数字）。这显著减少了内存使用并加速了推理。然而，原则上，更低的精度意味着更低的性能。同样的思想也可以应用于 KV 缓存本身，以保持长上下文在内存中。量化是一种常用的方法 [Dettmers et al., 2022, Dettmers and Zettlemoyer, 2023, Xiao et al., 2023]。或者，与其将所有权重转换为相同的精度，*混合精度*模式已被提出，为计算的不同部分使用不同级别的数值精度，以平衡速度和稳定性 [Micikevicius et al., 2017]。由于数值不稳定性，这种方法可能产生不确定的结果 [Yuan et al., 2025]。

**推测性解码（Speculative Decoding）** 优化推理效率的一项关键技术是*推测性解码* [Leviathan et al., 2023]。这种方法使用一个小型草稿模型快速生成多个 token，然后由大型目标模型并行验证。这允许更快的推理（高达 2-3 倍加速），而不牺牲大型模型的质量，有效地利用了缩放曲线上的不同点。

### 4.2.2 以数据为中心的优化

除了以模型为中心的方法外，文献强调，在训练高效模型时，数据质量和筛选往往比数据集的大小更重要 [Luo et al., 2025]。如果小模型在高度精选的高质量数据上训练，它们可以表现良好。因此，除了高效的模型架构外，创建良好的数据配方也很重要。以数据为中心的技术大致分为两类：从更广泛的数据池中*选择*最有用的部分，以及在好数据稀缺时*生成*新的合成数据。

#### 4.2.2.1 数据选择与筛选

与其在所有可用文本上训练，越来越多的工作表明，仔细选择*哪些*数据用于训练以及以什么比例混合，可以在相同计算预算下产生更好的模型。对于预训练，NVIDIA 的 *CLIMB* 框架 [Diao et al., 2026] 将大型语料库嵌入语义空间，对其进行聚类，然后迭代搜索最小化代理模型损失的数据混合比例。由此产生的 *ClimbMix* 数据集（4000 亿 token）使一个不到十亿参数的模型能够超越在更大但未筛选的语料库上训练的同类模型。同样的原则也适用于微调阶段：*LIMA* [Zhou et al., 2023] 表明，仅使用 1,000 个精心筛选的提示-响应对进行监督微调就足以产生一个强大的指令遵循模型，支持这样的观点：大部分知识在预训练期间获得，而对齐主要教会模型一种期望的响应*风格*。

#### 4.2.2.2 合成数据收集

当合适的数据不存在时，可以生成数据。*Textbooks Are All You Need* 方法用于 Microsoft 的 Phi 系列等模型 [Gunasekar et al., 2023]，展示了在干净的、教科书质量的合成数据上训练可以使一个相对较小的 13 亿参数模型超越十倍规模的模型。这类流程通常依赖前沿模型生成数据，结合 *LLM-as-a-Judge*（大语言模型作为评判者）评分来筛选最准确和最具教育意义的示例，以及严格的*去污染（Decontamination）*以确保合成数据不会泄露基准测试集并夸大报告的性能。这种方法对于推理数据特别有价值：通过在较大模型生成的逐步推理轨迹上训练，复杂的问题解决技能可以被蒸馏到较小的架构中（另见第 6 章）[Muennighoff et al., 2025, Arora and Zanette, 2026]。

#### 4.2.2.3 样本高效学习

除了合成数据之外，研究越来越关注模型如何从有限的自然数据中更高效地学习。诸如 *BabyLM 挑战赛* [Warstadt et al., 2023] 等项目聚焦于在严格的数据约束下训练模型（例如，1000 万到 1 亿 token）。这反映了人类儿童在早期发展期间接收到的语言输入量，推动了样本高效架构的创新，同时为认知上合理的语言习得提供了见解。

### 4.2.3 流行模型

在介绍了改进技术之后，看看流行的大型和小型模型如何在实践中应用这些技术是有用的。模型通常按其开放程度分类：闭源权重（专有）模型仅暴露 API，开放权重模型发布其训练后的参数，开源模型还额外共享训练数据和代码。在实践中，开放性是一个程度问题而非严格的类别，我们后续可能使用开放性指数来评价透明度 [Artificial Analysis, 2026]。大多数开放模型可以在 Hugging Face 等仓库中找到。下面，我们简要描述一些最流行的开放权重模型，它们被设计为足够高效以在消费级硬件上运行，以及它们用来实现这一目标的技术。这不是一个详尽的列表，而是在撰写本文时体现效率技术趋势及其规模的一些有影响力的模型的选择。

**Phi 系列** [Abdin et al., 2024]。Phi 系列是功能强大的小语言模型，足够高效以在移动设备上本地运行。Phi 模型背后的核心创新是其以数据为中心的训练方法。Microsoft 精选高质量、经过大量筛选的网络数据，并结合由较大模型生成的合成数据。这使得小型模型（如 38 亿参数的 Phi-3-mini）表现良好，可与大得多的模型如 GPT-3.5 和 Mixtral 的推理能力相媲美。

**Gemma 系列** [Mesnard et al., 2024]。Google 强调 Gemma 模型继承了 Gemini 强大的通用能力，特别是在文本、推理和编码方面，同时在其特定规模类别中推进了最先进水平，但关于其训练方法或数据知之甚少。

**OLMo 家族** [Ettinger et al., 2025]。OLMo（开放语言模型）家族由 Allen 人工智能研究所开发，旨在成为一个完全开源的模型。OLMo 项目开源了完整的训练流程，包括代码和数据：预训练数据集（Dolma）、训练和评估代码、训练日志和中间检查点。这种透明度使研究人员能够研究训练动态、数据影响和算法偏见。

**Qwen 系列** [Bai et al., 2023]。Qwen 家族代表了一套高性能的基础和指令微调模型，从不到十亿参数的密集模型到大型混合专家（MoE）架构。它们以多语言能力和在数学、编码及逻辑推理基准上的表现而著称。

**OpenELM** [Mehta et al., 2024]。Apple 的高效语言模型家族专为在边缘设备上高效运行而设计。逐层缩放策略在靠近输入的层中使用较小的潜在维度，在靠近输出的层中加宽它们。这在低参数量的情况下实现了高精度。

**gpt-oss** [Agarwal et al., 2025]。OpenAI 发布了两个开放权重的推理模型，使用高效的混合专家架构，针对智能体能力进行了优化。

**Mixtral 系列** [Jiang et al., 2024]。这些模型在开放权重生态系统中推广了稀疏混合专家（SMoE）架构（如 Mixtral 8x7B），允许大参数量但在推理时仅有少量活跃参数，以最大化效率。

**Llama 系列** [Grattafiori et al., 2024]。Meta 的 Llama 模型已被广泛使用。在大型数据集上训练（Llama 3 高达 15 万亿 token），从适合边缘设备的小型尺寸到 4050 亿参数的大型前沿模型，它们确立了开放模型中缩放定律的标准，并催生了微调模型和衍生模型的生态系统。

**DeepSeek** [Liu et al., 2025]。DeepSeek-V3 是一个大型混合专家模型（总共 6710 亿参数，每个 token 激活 370 亿），以其训练稳定性著称。它将多头潜在注意力（MLA）用于压缩的键值缓存，结合无辅助损失的专家负载均衡策略，并在 FP8 混合精度下训练，以较小的计算成本实现了前沿水平的性能。该系列还包括 DeepSeek-R1 推理模型。

**GLM** [Zeng et al., 2026]。由智谱 AI 开发的 GLM（通用语言模型）家族建立在训练早期就发展出的强大推理能力之上，并在整个训练过程中保持。最近的迭代针对智能体工作流和软件工程进行了优化，目标是工具使用和代码生成性能，而非仅仅是文本补全。

**Pythia** [Biderman et al., 2023]。EleutherAI 的 Pythia 是一套模型（从 7000 万到 120 亿参数），旨在支持对训练动态和缩放的研究。每个模型都在相同的数据上以相同的顺序训练，并发布每个模型的中间检查点，使得对能力、记忆和偏见如何在训练过程中出现的研究成为可能。

**BLOOM** [Scao et al., 2023]。BLOOM 是一个 1760 亿参数的开放获取模型，由 BigScience 协作研究项目产出。在 ROOTS 语料库上训练，涵盖 46 种自然语言和 13 种编程语言，它是最早优先考虑多语言覆盖和完全开放性的大规模模型之一，在负责任 AI 许可证下发布。

**SmolLM** [Allal et al., 2025]。Hugging Face 的 SmolLM 是一系列紧凑型模型（1.35 亿、3.6 亿和 17 亿参数），旨在实现高效的设备端部署，与 Phi 系列类似。其性能源于数据筛选：它在 SmolLM-Corpus 上训练，该语料库结合了高质量网络数据、Python 代码示例以及合成生成的（Mixtral）教科书和故事。

## 4.3 推理时计算

传统的缩放定律聚焦于*训练时*计算量与性能之间的关系。最近的研究将部分计算负担转移到了推理阶段：*推理时缩放（Inference-Time Scaling）*（或测试时计算）[Muennighoff et al., 2025]。模型不再将所有计算量花在训练期间，而是允许在推理时进行更长时间的思考。这通过生成的 token 数量或探索的推理路径来衡量，以产生更高质量的答案。因此，优化吞吐量（token/秒）变得至关重要：token 生成速度越快，模型在相同时间内能进行的推理就越多。增加以 token 计的推理时预算可以带来能力的显著提升 [Du et al., 2024]；最近的工作表明，最优分配测试时计算量可以使较小的模型在困难的推理任务上超越更大的模型 [Snell et al., 2024]。然而，这些收益并非保证的，取决于任务和所采用的特定搜索或验证策略 [Stechly et al., 2023]。除了性能之外，这一转变还重新框定了关于大语言模型是哪种系统这一更广泛的问题，我们将在第 6 章中详细探讨。

## 4.4 可持续语言模型

大语言模型训练和部署的大规模带来了重大的环境和经济影响。AI 训练和推理的能源消耗巨大，随后的冷却用水对供水管道造成了压力 [Li et al., 2025, Jegham et al., 2025]。测量训练的能源使用和碳足迹直到最近才进入标准报告 [Ding and Shi, 2024]。据报道，训练单个大型模型消耗的能源可与数百户家庭一年的用电量相当。训练像 BLOOM 这样的模型在考虑动态功耗和硬件制造的隐含碳后，排放了超过 50 吨二氧化碳当量 [Luccioni et al., 2023]。随着大语言模型在科学和社会中的使用不断增加，总碳足迹越来越多地由*推理*而非训练主导，特别是对于每天被数百万人使用的模型 [Ozcan et al., 2025, Wu et al., 2022, Samsi et al., 2023]。这创造了一个机会：在训练期间花费更多计算量来创建更小、更高效的模型（如第 4.1 节所述）可以显著降低部署的长期环境成本。

随着全球推理需求扩展到每天数十亿次查询，累计能源消耗和相关财务成本超过了初始训练投资 [Faiz et al., 2024]。在这一规模上部署大型模型需要庞大的数据中心基础设施，以及大量的电力和水消耗。因此，推动部署小语言模型（SLM）以实现可持续的大规模使用。通过最小化参数量和量化位数，小语言模型减少了每个生成 token 所需的内存带宽和计算量，提供了更绿色、更经济可行的解决方案。

**隐私与数据泄露** 除了环境问题之外，通过云 API 集中化大语言模型引入了隐私漏洞。当用户查询基于云的模型时，敏感的个人数据、企业知识产权或受保护的健康信息必须传输到第三方服务器。这造成了数据泄露的风险 [Aiyappa et al., 2023, Li et al., 2024]，无论是通过未经授权的拦截、对抗性提取攻击，还是模型对私人用户提示的无意记忆和随后的不当复述 [Chen et al., 2024, Maini et al., 2024, Liu et al., 2022]。

为了缓解这些隐私风险并减少对云基础设施的依赖，开发者可以从基于 API 的推理转向*本地设备端推理* [Qu et al., 2025]：

- **基于 API 的推理**：基于 API 的推理依赖强大的远程服务器。虽然这允许访问具有数千亿参数的前沿模型，但它受网络延迟影响，需要持续的互联网连接，并且固有地将用户数据暴露给云提供商。

- **本地推理**：本地推理直接在用户的硬件（如智能手机、笔记本电脑或边缘服务器）上运行模型。这确保了数据隐私，因为提示永远不会离开设备，同时还消除了网络延迟并保证了离线可用性。

本地推理受限于消费级和边缘硬件的物理限制。例如，内存和带宽是有限的。大语言模型推理是一个内存受限的过程。存储模型权重需要大量的 RAM 容量，而生成 token 需要高内存带宽。此外，大多数移动设备由电池供电。在移动设备或标准笔记本电脑上运行密集的矩阵乘法可能导致电池快速耗尽和热节流。为了使本地部署可行，开发者必须依赖推理时优化技术，如量化（例如 4 位）和推测性解码，同时利用日益普及的专为低功耗边缘 AI 设计的神经处理单元（NPU）。

## 4.5 结语

随着大语言模型的使用变得更加普遍，对快速响应的需求增加，大语言模型开发的重点正转向更高效的解决方案。因此，纯粹为了原始性能而扩展数据、计算量和模型规模的重点正在转向为*效率*而扩展。

虽然基本的幂律仍然成立，但重点已从简单地训练尽可能大的模型转向计算最优训练、推理时缩放，以及开发能在消费级和边缘硬件上运行的有能力的小语言模型的倡议。本章讨论的方向是互补而非竞争的：以模型为中心的技术（LoRA、GQA、MoE、量化、蒸馏）和以数据为中心的技术（精心的数据选择和合成生成）越来越多地在单个训练方案中结合使用。随着我们越来越接近数据墙，合成数据和架构效率的角色可能会变得更加重要，而以少做多的能力正在成为研究焦点。
