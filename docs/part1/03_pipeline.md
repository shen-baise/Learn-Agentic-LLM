# LLM 训练流水线

###### 本章学习目标

在本章中，你将了解语言模型是如何被训练的。具体而言，你将能够：- 描述基本训练流水线的主要阶段，并解释各阶段的目的：*数据获取、预训练（Pretraining）、微调（Finetuning）、偏好调优（Preference Tuning）*以及*推理（Inference）*。- 区分*预训练*与*微调*，并解释为什么偏好调优在它们之后而非之前进行。- 解释*编码器/解码器（Encoder/Decoder）*的区分如何决定模型所使用的训练目标。- 识别用于评估语言模型的常见*基准测试（Benchmarks）*，并说明每个基准旨在衡量何种能力。

## 3.1 训练模型

大语言模型的训练流水线遵循一套较为标准化的方法论：从一个参数随机初始化的模型架构出发，我们通过一个称为*预训练*的过程来训练语言能力的。在预训练阶段，我们将大规模文本语料库输入模型，以自回归方式对其进行训练。这一阶段的产出是一个基座模型（Base Model），它通常尚不适合特定的实际应用。因此，我们需要将其适配到下游任务或用途上。这一阶段称为*后训练（Posttraining）*，在此阶段我们向模型展示特定类型的额外数据，通过这些数据来激发模型的任务特定行为，例如指令遵循或分类任务。

### 3.1.1 编码器模型与解码器模型

正如我们在上一章中所看到的，存在两种主流的模型风格。一方面，编码器模型能够基于输入数据创建丰富的上下文化表示。然而，近年来的大多数成功都基于解码器模型。虽然编码器更擅长理解任务（分类、情感分析），但解码器在生成任务上表现出色。解码器模型在规模上不断增长，无论是可训练参数的数量还是可用的训练数据都在持续扩大。这使得模型在泛化到未见过的上下文方面展现出令人惊讶的能力。让我们更详细地了解一下纯解码器训练流水线中的相关步骤。

### 3.1.2 预训练/微调范式

当前训练流水线成功的一个核心特征是迁移学习（Transfer Learning）的使用。现代 Transformer 模型的标准应用方式之一是：取一个在大型通用数据集上训练过的模型，然后在新任务上重新训练它。模型先在大型通用语料库上进行*预训练*，然后在新任务上进行*微调*，而新任务只有少量数据。由于数据集较小，同时也因为预训练的权重已被迁移，所以新任务的微调过程很快——微调训练不必从零开始。这种迁移学习范式中的预训练/微调区分，是大语言模型训练流水线的核心。模型不必从头开始训练，而可以在新场景中复用已经学到的语言知识，从而加速训练过程。大型商业模型的预训练可能需要数月时间。通常，新任务是特定的（例如在某个领域进行问答，或进行情感分析）。对于新任务，将使用专门的数据集来微调模型。在微调过程中，模型权重的一部分会被谨慎地更新，以保留预训练模型的通用语言能力，同时获得对新任务的理解。将模型微调到一个新任务通常需要数分钟到数小时。

### 3.1.3 开放模型与封闭模型

流行的 LLM 包括 OpenAI 的 ChatGPT 系列 [Achiam et al., 2023, Ouyang et al., 2022]、Meta 的 LLaMa 家族 [Touvron et al., 2023]、Google 的 Gemma [Chowdhery et al., 2023] 和 Gemini [Anil et al., 2023]、Anthropic 的 Claude 家族、Moonshot AI 的 Kimi、DeepSeek [Guo et al., 2025]，以及 Qwen [Bai et al., 2025] 等。这些模型之间存在不同程度的开放性。例如，模型的训练数据可以公开，模型的网络架构可以披露，训练好的权重可以发布。然而，商业模型背后的公司很少公布其模型和训练过程的所有要素，因为它们希望保持一定的竞争优势。作为回应，科学界开发了完全开源的模型，如 BLOOM [Le Scao et al., 2023]、Pythia [Biderman et al., 2023] 和 OLMo [Groeneveld et al., 2024]，以促进对大语言模型工作原理的集体理解。对于这些模型，训练流水线的所有要素都是公开的，它们也是本章的重点。我们还将着重介绍某些商业模型的特定方面。虽然这些模型都基于 Transformer 架构，但各个组件及其整体布局之间存在细微差异，例如为了利用硬件差异或其各自开发者开发的特定优化。例如，Google 针对其基于 TPU 的计算基础设施优化了 Gemini [Jouppi et al., 2023]。我们将在第 4 章中广泛讨论对架构的进一步改进。

## 3.2 训练流水线

我们现在将更详细地描述标准训练流水线的各个步骤。LLM 是通过一个包含不同训练阶段的复杂流水线构建的 [Radford et al., 2019, Minaee et al., 2024]。我们将按照图 3.1 所示来描述各个阶段。各阶段的组合通常被称为训练*配方（recipes）*，因为它们标明了模型被训练的顺序。在每个阶段，可能会使用新的数据集和新的损失函数。每个阶段都旨在赋予模型特定的能力。随着我们讨论各个阶段，这一点将变得清晰。

### 3.2.1 数据获取

流水线的第一步是获取数据。通常使用大规模的通用文本语料库 [Brown et al., 2020]。这些语料库由无需人工标注的原始文本组成。这些数据通常从经过策划和未经策划的在线来源中汇总，然后通过清洗启发式方法进行精炼，以减轻有害、隐私或版权内容的影响。用于预训练的语料库规模巨大。现代 LLM 在网页级别的数据规模上进行训练，通常达到数万亿 token 的量级。以下是一些数据集示例：

- **Common Crawl**：一个大规模的、非营利性的网络快照，包含数十亿网页；替代来源包括 [https://archive.org](https://archive.org)。虽然其规模无与伦比，但数据质量仍存在争议 [Baack, 2024]。许多衍生数据集，如 C4（Colossal Clean Crawled Corpus），提供了经过过滤的英文网页文本子集 [Raffel et al., 2020]，以提高数据质量。

- **Dolma 3**：一种数据混合方案，旨在最大化在多样化任务集上的性能。它被用于 OLMo 开源/开放数据项目 [Ettinger et al., 2025, Soldaini et al., 2024]。

- **SmolLM3**：采用大规模三阶段训练策略，使用 11.2 万亿 token，动态混合网络、数学和代码数据，以优化推理和知识获取能力 [Bakouch et al., 2025]。

最近的研究强调，数据多样性与数据规模对于提升跨领域知识和下游泛化能力同样重要 [Gao et al., 2020]。名为 *The Pile* 的语料库就是专门作为异构语料库创建的。例如，在 The Pile 上训练的模型在编码效率（Bits Per Byte, BPB）方面表现出显著提升，涵盖了不同的领域，如 GitHub 代码仓库、医学论文和哲学文本（见图 3.2）。因此，它常被用作基准测试，在 Pile BPB 上的成功表现可作为模型世界知识和复杂推理能力的指标。

![图 3.2 The Pile 数据集的数据源概览](/figures/the_pile_sources.png)

图 3.2：The Pile 数据集的数据源概览 [Gao et al., 2020]。

> ^1 Bits-Per-Byte（每字节比特数）是一种与分词器无关的信息论指标，衡量每个符号所需的平均比特数，反映编码效率，另见第 3.3.2 节。

预训练数据的策划需要定义复杂的数据清洗流水线，将来自多个来源的原始数据转换为单一的清洗后纯文本文档集合。通常，这一过程侧重于质量保证和安全性。策划过程从来源优先级排序开始，将混合比例偏向高质量来源，如维基百科、书籍和其他已知的策划来源。此外，为确保语料库的完整性，研究人员应用降噪启发式方法来去除样板文本、导航菜单和可能不当的内容。而且，去重工作在 URL 和文档两个层面进行；这对于防止模型记忆冗余信息和在重复数据上过拟合至关重要。除了准确性之外，流水线还必须选择符合安全和伦理约束的数据。这通常也通过基于启发式的过滤来实现。此外，还实施了毒性检测系统以移除仇恨言论，尽管这些方法的效果往往参差不齐。这一阶段的一个重大挑战是偏见缓解，因为自动化过滤器可能会无意中标记和压制以特定方言（如非裔美国人英语）撰写的合法内容，导致训练集中意外地排斥了多元化的声音。

### 3.2.2 预训练

训练流水线的第二步是在策划好的语料库上预训练模型，这一过程产出一个通用的自然语言模型。此阶段在无标签文本上使用自监督 Transformer 方法 [Vaswani et al., 2017]。

为了获取语言的内部表示、概念语义关系和世界知识，模型使用类似掩码填词的任务进行训练。在此类任务中，目标是根据大规模语料序列的前文上下文（即文本、图像块的表示）来预测被遮蔽的 token。这一过程是自监督的（不需要人工标注数据），并且已知能够以各种形式产生丰富的语言表示、概念间关系和世界知识。

形式上，语言建模目标基于一个大小为 $k$ 的已有 token 窗口，最大化句子 $U=\{u_0,...,u_n\}$ 中 token 的概率（公式 3.1）。$L(U)$ 是*语言建模损失*。

$$L(U) = \sum_i \log P(u_i | u_{i-k}, ..., u_{i-1}; \Theta) \quad (3.1)$$

语言模型通过可训练参数 $\Theta$ 来估计这些概率，并通过梯度更新进行优化。鉴于模型规模从数百万到超过一万亿参数不等，需要大规模数据集来确保收敛。

在此训练阶段，采用*教师强制（Teacher Forcing）*：模型做出预测，但将真实 token——而非模型自身的输出——作为下一步的输入。相比之下，在推理时的自回归生成中，模型必须依赖自身的预测作为后续 token 的输入。Token 通过运行适当的*分词器（Tokenizer）*来创建，如第 2.1.4 节所述。

在预训练中，一个关键挑战是确保模型在数万亿次梯度更新中高效学习并保持稳定。随着时间推移，不同的策略逐渐发展出来，旨在控制训练过程。其中一种策略是*课程学习（Curriculum Learning）*。在人类学习中，我们先学习简单的概念（如加法），然后再处理更困难的概念（乘法、对数）。在语言建模中，这一思想被应用于数据混合或数据课程中。研究者不是同时训练所有数据类型，而是选择特定的数据源混合进行训练，参见图 3.3 中的示例。混合方案的创建涉及根据难度对数据进行策略性排序。在训练课程中，我们从易于学习的通用网络爬取数据开始，然后在后续阶段转向更难的高质量推理数据（数学和代码）。其基本思想是这有助于模型更快地收敛到更复杂的逻辑 [Bengio et al., 2009]。

### 3.2.3 微调

预训练之后是后训练，其中第一个重要的训练步骤是微调。LLM 很少以通用的自动补全式"预测下一个词"的方式使用，人们更倾向于用它们来回答问题、提供建议和回忆信息。微调是指取一个已经学习了通用语言模式的预训练模型，然后在一个更小、更具体的数据集上进一步训练它的过程。在微调中，我们在有标签的数据集上将通用模型应用于特定（窄领域）任务，使用监督学习方法。一种流行的参数高效方法是低秩优化（Low-Rank Optimization），它只微调参数的一小部分 [Hu et al., 2021, Wei et al., 2022, Minaee et al., 2024]。

**监督微调（SFT）** 微调可以应用于许多专门任务。最通用的模型使用*监督微调*来使其能够遵循指令并执行推理步骤 [Ettinger et al., 2025]。监督微调步骤对于较小的模型尤为重要，提供了一种在通用对话、推理和函数调用能力方面实现显著提升的高效机制。

监督微调也用于更专门的任务，如毒性降低。WildChat [Zhao et al., 2024] 提供了超过一百万条真实用户与 ChatGPT 的交互记录，记录了人类以不同复杂度和毒性水平提示 LLM 的方式。为了学习推理能力，OpenThoughts [Guha et al., 2025] 包含逐步推理链，这些推理链从高级模型中蒸馏而来，以增强数学、科学和编码方面的问题解决能力。人工获取的数据由合成数据补充，合成数据涉及使用更大的教师模型（如 GPT-5）生成指令和回复，以填补特定的数据空白并扩大训练规模 [Zhang et al., 2026]。

微调不仅涉及通用的指令遵循或推理。其他任务可以包括从一种语言到另一种语言的翻译，或在医疗保健和客户服务领域的问答。特别是对于工业应用，当任务范围较窄且模型较小时，微调是一项富有成效的工作。

在第 11 章中，我们将讨论 LLM 的工具使用，这是智能体 LLM 的一个核心方面。工具使用的训练也在训练流水线的监督微调步骤中进行 [Wei et al., 2022, Minaee et al., 2024]。

此外，微调在建立模型的人设和深化其专业知识方面也起着关键作用。例如，组织可以训练模型采用特定的语气风格，例如使客服机器人保持一致的品牌形象——无论是富有同理心的正式风格，还是机智幽默的随意风格。最后，深度领域知识的注入使模型能够掌握小众领域中复杂的术语和逻辑，如特定行业的专利信息或调试专有遗留代码。最终，微调将通用预测器转化为专门领域的专家，通常使更小、更高效的模型能够在特定任务上超越更大的基座模型。

### 3.2.4 偏好调优

早期模型中浮现的一个问题是，训练往往会放大训练数据中极端的、社会不可接受的文本并使其失控，挤占了温和的观点。从那时起，LLM 变得在社会上可接受的一个关键步骤是，流水线需要包含一个将模型调优为以社会可接受方式行为的阶段。这个阶段称为*偏好调优*。

在这个阶段，我们将微调后的模型与用户期望进行对齐（偏好对齐，Preference Alignment）。此步骤的目标是改进模型，使其给出社会可接受的回答，防止仇恨言论，减少幻觉，并提高指令遵循能力。

偏好调优的标准方法包括：基于人类反馈的强化学习（RLHF）[Ouyang et al., 2022]，它训练一个奖励模型来近似人类价值观；以及直接偏好优化（DPO）[Rafailov et al., 2024]，它直接从偏好数据中优化策略。RLHF 的高层概览如图 3.5 所示。为了解决人工标注的瓶颈，现代流水线越来越多地利用基于 AI 反馈的强化学习（RLAIF）[Bai et al., 2022]，其中更强的模型生成偏好信号。

实现与人类价值观的对齐并非易事，我们通常区分*安全对齐*、*价值对齐*和*偏好对齐*。在最后一种情况下，一个复杂性在于偏好是主观的（如写作风格），因人而异。

**价值对齐** 在更高层次上，价值对齐侧重于确保模型的底层原则和世界观与广泛的人类伦理产生共鸣。与个体偏好不同，这涉及将模型锚定在公平、有益和诚实等高级概念上。在实践中，这意味着模型受一套书面原则（*宪法*）的约束，以确保其遵守开发者制定的政策。然而，这种价值对齐通常会导致权衡——为安全性和有益性优化模型也会降低其在其他能力上的表现，如事实回忆或创造力 [Lin et al., 2024]。这种权衡也被称为*对齐税（Alignment Tax）*。

**安全对齐** 安全对齐是为模型行为设定硬性边界以防止灾难性或有害输出的过程。如果偏好对齐可能侧重于语气，价值对齐侧重于观点，那么安全对齐则侧重于对抗鲁棒性和对恶意提示的拒绝。确保安全的方法示例包括*红队测试（Red Teaming）*，即对模型进行严格的越狱尝试以识别漏洞；以及*护栏机制（Guard Railing）*，即对高风险回复的特定拒绝边界进行过滤。

**目标对齐** 最后，对于存在客观真理的领域（如数学或编码），采用称为*可验证奖励强化学习（RLVR）*的方法 [Lambert et al., 2024]。与标准 RLHF 不同，RLVR 通过利用真实信号来优化客观正确性，从而稳健地提升推理能力。示例包括可编译的代码或正确的数学解答。在后一种情况下，通常使用*组相对策略优化（GRPO）*算法 [Guo et al., 2025]，它是*近端策略优化（PPO）*的一个变体，在增强数学推理能力的同时优化了 PPO 的内存使用。它通过从策略模型中采样多个回答，并使用它们的相对质量（由验证器评估）来计算奖励。模型不是依赖人类标签来学习什么是好的回答，而是从确定性验证器那里获得直接奖励（+1 或 -1）[Guo et al., 2025, Shao et al., 2024]，见图 3.6。

### 3.2.5 推理

训练流水线的最后一步是推理步骤。这是训练好的模型最终被使用的步骤。在这里，用户终于可以与模型进行交互。我们终于可以享受到训练工作的成果。

在推理时，我们使用自然语言提示（指令和问题）来从模型获取回答。提示（Prompting）是使用 LLM 回答问题的首选方式。推理结果可能对提示的表述方式敏感。使用某些词语或在提示中重新排列词语的顺序，都可能影响模型的回答。这种敏感性催生了*提示工程（Prompt Engineering）*和*上下文工程（Context Engineering）*，这些技能已成为 LLM 用户的重要能力 [Sahoo et al., 2024]。

有趣的是，正如我们在上一章中讨论的，在参数规模超过数千亿的解码器模型中，一种新的学习方式出现了：*上下文学习（In-Context Learning, ICL）* [Brown et al., 2020, Wei et al., 2022]。上下文学习是一种方法，其中提示包含少量示例以及一条指令。这些示例将模型引向某个方向，模型利用它们来学习答案。ICL 是提示内少样本学习（Few-Shot Learning）的一种形式。ICL 也是一种不改变模型参数的学习方式——它是无需参数训练的示例学习 [Dong et al., 2022]。

在本书的后续部分中，我们将看到许多上下文学习使用方式的示例，例如在智能体框架中。推理时的上下文学习是智能体 LLM 的主要驱动力。

### 3.2.6 结语

我们现在已经描述了典型 LLM 训练流水线的各个阶段。请注意，我们描述的流水线是一个典型方法的示例，不同模型的训练方式各有不同。当前的现代训练流水线是复杂的，训练成本高昂。训练流水线的创新是当前研究的主题，参见例如 Guo et al. [2025]、Du et al. [2025]。

能够快速获得预测结果是关键的，为此已经开发了多种技术来加速这一过程。例如，在推理努力和回答质量之间取得平衡非常重要。*测试时缩放（Test Time Scaling）*的研究正是探讨这种权衡。更高的推理时投入需要更多的计算时间，但可能产生更好的回答。我们将在第 4 章中讨论这些及其他优化技术。

## 3.3 基准测试与性能

在使用流水线训练好模型之后，我们希望了解模型的表现如何。LLM 使用多种建模技术、针对不同任务、在不同数据集上创建。因此，它们通常获得了卓越的能力。例如，LLM 在自然语言理解任务（GLUE、SQUAD、Xsum）[Wang et al., 2018, 2019, Rajpurkar et al., 2016, Narayan et al., 2018]、翻译 [Kocmi et al., 2022, Papineni et al., 2002, Sennrich et al., 2015]、问答任务 [Roberts et al., 2020] 以及诗歌创作 [Zhang and Eger, 2024] 等领域表现出色——这里仅列举了几个领域。LLM 的广泛适用性展示了其多功能性，尽管该领域的快速发展以及持续的研究工作，引发了许多关于 LLM 在众多领域和上下文中能力的开放性问题。

我们现在将讨论常用于测试模型性能的基准测试。

### 3.3.1 常见任务

让我们更仔细地看一些常见的 LLM 任务。这些任务大致可以归入我们之前介绍的两大语言处理类别：自然语言理解（NLU）和自然语言生成（NLG）。根据类别、具体任务形式和底层数据的不同，性能指标也会有所不同。我们将分别讨论每一项。

请注意，*性能*是一个含义模糊的术语。在 NLP 中，它通常用于指*任务性能*（准确率），而非*计算性能*（速度）。虽然确切的评估标准因任务而异，但现代评估实践主要关注任务性能。然而，我们对 LLM 发起多少次调用、以及多快能从模型获得回答，在当代基准测试中取得高分也同样重要，正如我们将在后续章节中看到的。

### 3.3.2 指标

为了监控或报告 LLM 的（任务）性能，根据我们所处的训练阶段，使用不同的指标。

**预训练指标** 在预训练中，我们最感兴趣的是了解模型是否能够准确预测下一个词。标准指标是*困惑度（Perplexity）*，如公式 3.2 所示。困惑度衡量模型在预测下一个 token 时的不确定性，与交叉熵损失函数直接相关。低困惑度表明模型对正确的下一个 token 赋予高概率。困惑度越低越好。

$$\text{PPL}(X) = \exp\left(-\frac{1}{N} \sum_{i=1}^{N} \log P(x_i | x_{<i})\right) \quad (3.2)$$

$$\text{BPB} = -\frac{1}{B} \sum_{i=1}^{N} \log_2 P(x_i | x_{<i}) \quad (3.3)$$

困惑度是按 token 计算的；将困惑度调整为按词边界计算需要仔细的归一化 [Pimentel and Meister, 2024]。而且，即使经过调整，它仍然是特定于分词器的，因为不同的分词器可能导致不同的子词和因此不同的概率分布。作为替代，*每字节比特数（Bits-Per-Byte, BPB）*如公式 3.3 所示，将损失归一化到字节级别，从而能够在使用不同分词方案的模型之间进行公平比较 [Borgeaud et al., 2022]。它衡量编码单个字节数据所需的平均比特数。

**后训练指标** 在后训练和推理中，当模型用于问题解决、生成或推理时，我们关注基于真实数据的确定性成功率。通常，任务被设置为多选题问答格式，其中只有一个正确答案。对于这类任务，我们通常报告*准确率（Accuracy）*，即给出正确回答的问题所占的百分比。准确率越高越好。

在常规设置中，模型需要在一次尝试中提供答案。然而，由于从语言模型中采样是一个随机过程，我们可以请求额外的尝试，并查看正确答案是否在其中。这在 *Pass@K* 指标中被形式化：模型在第 $K$ 次尝试时正确解决的问题百分比；越高越好。$K$ 的常见值包括 1、5、10、100。

### 3.3.3 常见基准测试

虽然衡量 LLM 的性能仍然是一个活跃的研究领域，但许多数据集已成为报告其通用能力的常用工具。这些数据集仅用于*评估*模型质量，不作为额外的训练数据。因此，它们充当半标准化的基准测试。向领域标准迈进的持续努力，如 MLCommons [Thiyagalingam et al., 2022]，显示出对客观、可靠评估方案日益增长的需求。

**数据污染** 现代基准测试面临数据污染的风险 [Balloccu et al., 2024]。随着预训练数据规模的增加（通常占互联网总规模的相当大比例），域内数据和域外数据之间的界限变得越来越模糊，特别是考虑到商业厂商通常不指定其训练数据的来源（出于商业利益或其他原因）。因此，当我们希望衡量对未见数据的真正泛化能力时，我们需要确保模型之前没有见过这些数据（我们希望防止*数据污染*）。基准测试通常会托管一个公开的、免费可访问的数据集供开发者快速实验，同时维护一个商业厂商受限访问的私有数据集，以防止数据污染。此外，为了保持基准测试在未来的有效性，开发者通常会积极更新基准测试中的样本。

## 3.4 结语

在 LLM 开发领域，商业 LLM 开发者（如 Anthropic、OpenAI、Google、DeepSeek、Mistral）已经习惯发布技术报告，向专业公众通报模型在各种流行基准测试上的表现。通常，这类技术报告作为预印本发布，未经学术同行评审，而且出于商业原因，许多完全科学可重复性所需的细节（如数据配方、模型架构）被省略。尽管如此，这些报告提供了有用的信息，可以推导出关于 LLM 能做什么和不能做什么的洞见。

首先，我们发现现代 LLM 在基准测试上表现出明显的性能层次：它们已经有效地解决了广泛的通用知识任务，但在掌握复杂推理和自主智能体任务方面仍有困难。在静态知识和专业考试基准测试（如 MMLU 和 TruthfulQA）上，前沿模型（如 GPT-5.2、Gemini 3 Pro 和 Claude 4.5 Opus）在撰写本文时已接近饱和，持续得分超过 85-90%，并超越了人类专家基线。新一代推理模型（如 OpenAI 的 o1、DeepSeek-R1 和 Qwen-3.5）最近取得了巨大进展，将数学和科学的通过率从较低的百分比提升到了专家水平。尽管取得了这些进展，软件工程基准 SWE-bench 仍然是可靠性的终极压力测试；虽然顶级编码智能体的得分已从可忽略不计（<2%）上升到可观的水平（在验证子集上为 40-50%），但回答编码问题与自主修复真实代码仓库问题之间的差距，仍然是现代 AI 面临的重要障碍。

**开放性问题** 关于 LLM 能力来源的开放性问题仍然存在。随着流水线变得日益复杂，无论是在训练方面（*什么数据重要？哪些训练步骤最重要？*）还是推理方面（*如何提取高质量的推理轨迹？*），得出结论是困难的。例如，一个开放性问题在于预训练和后训练哪个更重要，以及知识主要来自预训练、后训练仅用于寻找良好的任务接口 [Zhou et al., 2023]。

本书的后续部分将讨论后训练和推理时推理方法以及智能体训练方法。但首先，我们将在下一章中讨论缩放定律。
