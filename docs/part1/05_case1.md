# 案例1：从零构建大语言模型

## 学习目标

在本案例研究中，你将学习如何训练自己的模型。具体而言，你将能够：

- 解释类ChatGPT大语言模型的端到端**训练流程**（training pipeline），区分每个阶段的目的与机制：分词（tokenization）、预训练（pre-training）、中间训练（mid-training）和监督微调（supervised fine-tuning）。
- 配置并训练一个字节对编码（Byte Pair Encoding, BPE）**分词器**（tokenizer），并阐述选择词表大小时涉及的权衡。
- 在机制层面描述Transformer**架构**（architecture）：注意力头（attention heads）、层深度（layer depth）、嵌入维度（embedding dimensions）。你将探究这些超参数如何与模型容量和计算预算相互作用。
- 在标准**基准测试**（benchmarks）（ARC-Easy、ARC-Challenge、GSM-8K）上评估训练好的语言模型，并批判性地解读结果，包括失败模式。
- 批判性地反思大语言模型训练中的**伦理**、环境和可及性维度，包括成本作为准入门槛以及数据策展作为价值负载选择的影响。
- 访问和浏览与开放获取大语言模型相关的信息，包括阅读模型卡（model cards）、训练报告、阅读与训练大语言模型相关的代码，以及其他类型的**模型中心条目**（hub entries）。

## 5.1 构建聊天机器人

我们将通过一个实际案例，涵盖现代类ChatGPT语言模型的完整生命周期。我们使用 *nanochat*[^1]，这是一个极简的、单代码库的、全栈的指令跟随大语言模型实现，由Andrej Karpathy于2025年4月发布。与他之前仅涵盖预训练的 *nanoGPT* 不同，nanochat实现了完整的训练流程：一个字节对编码分词器、在网页文本上进行预训练，随后在基准数据集上进行监督微调（SFT），一个推理服务器，以及一个聊天网页界面。代码主要使用纯Python编写，依赖极少，因此易于使用和扩展。代码库包含大约8,000行Python代码和少量Rust代码[^2]。nanochat的性能令人印象深刻：一个GPT-2级别的LLM（2019年训练成本约为43,000美元 [Radford et al., 2019]），仅需48美元（约8xH100 GPU节点运行2小时）。虽然这一计算量在大学的标准学生项目中并不常见，但我们可以缩小实验规模，使其适合动手课程作业。重要的是要认识到，从原始字节到一个可工作的聊天助手，每一个梯度更新和每一个设计决策都是可见的。我们将通过四个任务带你走完nanochat的完整流程，这些任务你都需要完成。由于课程中的GPU预算有限，你将训练一个**小型**模型（depth 4，具体取决于硬件可用性，参见第5.3节）；然后你将借助一些理论和已发布的（nanochat）基准测试结果，反思在更大规模下可能发生什么。

[^1]: https://github.com/karpathy/nanochat

[^2]: 如果这个数字听起来很大，值得注意的是，相应的专有系统代码量可达数百万行。nanochat旨在成为一个小型的、自包含的版本。

## 5.2 背景：Karpathy的nanochat

本案例研究将让你直接、动手体验现代LLM训练流程的每个阶段，从输入文本到部署聊天助手。这一经验将把第2-4章中的理论概念扎根于具体的、可调试的代码中。nanochat开箱即可配置为训练一个计算最优模型，只需设置一个复杂度旋钮：`--depth`，用于指定Transformer层的数量。所有其他超参数——嵌入宽度、注意力头数量、学习率调度、训练时长、权重衰减——都以近乎最优的方式自动推导。这使得配置空间可控，同时保留了理解每个参数作用的完整教育价值。训练流程按照现在应该已经熟悉的阶段进行，下面简要描述。

**预训练（Pretraining）** 模型在大约60亿个token上进行训练，这些数据来自CLIMBMix [Diao et al., 2026]，一个基于聚类的迭代自举数据混合语料库。一个depth-24（约14亿参数）的模型在4xH100节点计算集群上训练约4小时，可达到2.41的验证损失（0.717 bits-per-byte）。

**监督微调（Supervised Finetuning, SFT）** 从预训练检查点出发，模型在指令跟随和推理数据的混合集上进行微调：SmolTalk [Ben Allal et al., 2024]（46万条通用对话）、MMLU（多选知识问答题，3个epoch）、GSM-8K（小学数学题，4个epoch）、身份对话，以及合成拼写任务——总共约110万条训练样本。注意，交叉熵损失**仅在助手token上**计算，不在用户提示上计算，这镜像了InstructGPT的训练过程 [Ouyang et al., 2022]。在每个训练阶段之前，使用Rust实现在20亿字符上训练一个BPE分词器，在不到一分钟内生成一个包含32,768个token的词表。开箱即包含一个网页推理服务器和一个轻量级JavaScript聊天界面，允许立即与训练好的模型进行交互。

**补充资源** 两门免费课程为本案例研究的内容提供了互补视角。**Hugging Face LLM课程** [Hugging Face, 2022] 介绍了 `transformers`、`datasets`、`tokenizers` 和 `accelerate` 库，以及当前大多数开放权重模型分发和评估的Hugging Face Hub。Mathieu Labonne的 **LLM课程** [Labonne, 2023] 提供了实践路线图，涵盖预训练数据策展、参数高效微调（LoRA、QLoRA）、偏好对齐（DPO、PPO、GRPO）、量化（GGUF、GPTQ），以及生产推理服务（vLLM、TGI）。这些资源共同将nanochat置于更广泛的开源LLM生态系统中，并在任务3和任务4中被明确引用。你也可以自由浏览其他额外资源。强烈建议在报告中根据需要链接和引用来源。

**计算资源** 不需要专用计算资源。你可以使用自己的笔记本电脑（带GPU）或更大的计算机。实验计划为每次运行最多约8小时完成。预训练使用 `--depth 4` 配置；仅当你的硬件不支持更大模型时，才可使用 `--depth 2`。**不要**尝试 depth >= 12，除非你拥有相当强大的硬件。

## 5.5 任务1：分词

### 5.5.1 操作内容

使用nanochat的Rust分词器训练器，在CLIMBMix数据集的5亿字符样本上训练一个BPE分词器。运行两个实验：一个词表大小为 **8,192** 个token，另一个为 **32,768** 个token。

### 5.5.2 提交内容

- 一个可复现你的分词器训练运行的简短脚本。

- 一个报告章节（最多1页），用你自己分词器输出的证据回答以下问题：

1. 什么是BPE，它与词级和字符级分词有何不同？为一个具体示例绘制一棵合并树（你可以在数据中寻找一个例子，或自己构造一个。不要重复使用已有的示例！）。确保同时包含你的合并计数。
2. 词表大小如何影响固定文本样本的**压缩比**（compression ratio，每字符的token数）和**序列长度**（sequence length）？展示你的两个分词器在英文文本上的测量结果。
3. 为什么词表大小对下游语言模型很重要？在你的回答中，考虑嵌入矩阵大小、softmax分母，以及为罕见token学习可靠表示的挑战。

## 5.7 任务3：中间训练与监督微调

### 5.7.1 操作内容

回顾nanochat仅执行两个训练阶段：预训练和SFT。然而，在本书中我们讨论过，以中间训练（mid-training）形式增加的额外阶段可以帮助模型表现得更好。在这个任务中，你将通过修改 `scripts/chat_sft.py` 实现一个新的中间训练阶段。目标是将**推理适应**（reasoning adaptation）（中间训练）与**指令跟随**（instruction following）（SFT）分离开来，并实证测量其效果。

**阶段1 — 中间训练** 修改 `chat_sft.py` 中的 `train_tasks` 列表，使其仅包含推理和知识任务：MMLU和GSM-8K。移除所有其他对话和拼写数据。从你的预训练基础检查点运行 `chat_sft.py`，并保存生成的检查点。

**阶段2 — SFT** 再次修改 `chat_sft.py`，使 `train_tasks` 仅包含SmolTalk。你还需要做一个小改动，使脚本加载你的阶段1检查点而非基础预训练模型。检查 `chat_sft.py` 中的 `load_model` 调用作为起点[^4]。从你的阶段1检查点运行 `chat_sft.py`，以在中间训练之后进行SFT。在每个阶段之后，使用 `scripts/chat_eval.py` 在ARC-Easy、ARC-Challenge和GSM-8K上进行评估。

**健全性检查：** 在运行阶段1之前，检查数据：打印MMLU和SmolTalk数据集的前几行，以了解其格式和内容。确保你能回答：每个数据集贡献了多少训练样本，单个训练样本是什么样的？

[^4]: 提示：阅读 `nanochat/checkpoint_manager.py` 以了解检查点的定位方式。

### 5.7.2 提交内容

- 两个检查点，每个阶段一个（中间训练和SFT）。

- 每个阶段后在ARC-Easy、ARC-Challenge和GSM-8K上的评估分数，以表格形式报告。这应该是报告的一部分（见下文）。

- 一个报告章节（约3页），涵盖：

2. **损失掩码**（Loss Masking）：为什么SFT损失仅在助手token上计算？构造一个具体的token级示例，说明有掩码和无掩码时损失分别是什么样的。

3. **数据集分析**：对于每个阶段，描述所使用的数据集、其大致规模，以及为什么为该阶段选择它。数据集训练分割中可能嵌入哪些价值观或潜在偏见？这些如何塑造模型行为？
