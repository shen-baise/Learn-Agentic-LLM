# LLM 中的多步推理

## 学习目标

在本章中，你将学习语言模型如何通过**多步推理（multi-step reasoning）**来解决更复杂的问题。具体来说，你将能够：

- 描述**思维链（Chain of Thought）**的概念：我们如何利用上下文学习来引导 LLM 在回答查询时采取中间步骤，从而为更复杂的查询提供更好的答案。
- 描述推理方法如何极大地提升了 LLM 的**能力**，以及为什么这种能力对于智能体式 LLM 在现实世界中切实行动至关重要。
- 编写你的第一个**智能体框架（agentic harness）**：一个以不同提示调用 LLM 的小算法。智能体框架管理提示和 LLM 的回复。
- 解释**自我反思（self-reflection）**：LLM 可以被框架以不同角色调用，例如**评估**答案或**生成**子问题。LLM 通过反思来改进自己的答案。
- 理解**记忆（memory）**所扮演的角色：框架如何跟踪智能体的状态，以及框架如何使用该状态来管理提示。
- 使用**可验证奖励的强化学习（Reinforcement Learning with Verifiable Rewards）**概念：其中推理时的推理结果被用于微调。

## 6.1 上下文推理

正如我们在第 3 章中所述，在大型模型中（参数量超过数千亿），LLM 中出现了一种新型学习方式。它被称为**上下文学习（In-Context Learning, ICL）**或**提示学习（prompt-learning）**[Brown et al., 2020]。这是一种重要的学习方法，我们将在本节中更详细地讨论。然后，我们将讨论常见的基准测试以及用于多步推理的思维链方法。

### 6.1.1 上下文学习

上下文学习 [Dong et al., 2022] 不发生在训练时，而发生在推理时，通过在使用模型回答问题时在 LLM 提示中提供的示例来学习。这些示例使解码器模型能够访问存储在 LLM 中的相关知识。由于这种丰富的知识，上下文学习只需少量示例就能找到准确的结果，这就是为什么它是一种所谓的**少样本学习（few-shot learning）**方法。少样本学习之所以成为可能，得益于模型的大规模，其中包含了关于许多主题的丰富且多样的知识。

**学习，而非训练** 上下文学习与微调或预训练之间的一个主要区别在于，上下文学习不改变 Transformer 的参数。由于在推理时不改变模型参数，它不是一种**参数训练**方法；然而，由于它确实从提供的示例中学习答案，它是一种**学习**方法。一个结果是，ICL 具有遗忘的缺点：由于模型参数保持不变，所有学习到的信息在 LLM 调用之间都会丢失。要在 LLM 调用之间共享信息，必须将之前的结果作为额外的学习示例添加到下一次调用的提示中的上下文窗口中。

**上下文窗口** 上下文学习是如何工作的？LLM 中写入提示的部分称为其**上下文窗口（context window）**。解码器模型在这个上下文窗口内从提示中提供的示例中学习。需要注意的是，所有用于学习答案的示例必须一起在上下文窗口中提供——它们必须适合提示。通常，上下文窗口的大小限制为几千个 token，只能提供少量示例：ICL 所能执行的仅仅是少样本学习。当我们希望学习的信息量增长时，这就变得有问题了，因为上下文窗口的大小通常是有限的。我们可以说，上下文学习遭受着长期记忆丧失的困扰。

**示例** 在上下文学习中，由少量演示上下文组成的提示与查询问题拼接在一起，被送入语言模型的上下文窗口 [Liu et al., 2023]。然后模型将通过前向传播生成答案。例如，当任务是社交媒体帖子中的情感识别时，*I missed the bus today*（我今天错过了公交车）后面可以跟 *I felt so []*（我感觉很 []），模型可能会回答 *bad*（糟糕）。或者，对于翻译任务，我们可以在 *I missed the bus today* 后面跟 *French: []* 来请求翻译。提示包含模型能识别的背景信息，从而选择所需的模型上下文。

**少样本学习与机器学习的圣杯** 当语言模型包含足够的知识时，上下文学习就能发挥作用，使模型能够根据提示中提供的（少量）示例进行泛化。用户在提示中提供一些相关示例，以引导 LLM 选择正确的背景知识来回答提示中的指令。包含少量示例的上下文被称为执行少样本学习。只包含指令、没有示例的上下文被称为执行零样本学习（zero-shot learning）。ICL 是一种少样本学习形式，在研究人员中引起了极大的关注。

在传统的机器学习中，模型 $f$ 在数据集上进行训练。为了在复杂问题上实现高准确率，数据集必须包含大量示例。传统机器学习是一种**多样本学习（many-shot learning）**形式，需要大量（昂贵的）训练轮次来训练模型参数。另一方面，上下文学习是廉价的，只需要少量示例加上一次通过解码器模型的前向传播（因为昂贵的训练已在预训练阶段完成）。少样本学习可以说是机器学习的圣杯：一个能够廉价泛化的模型。

**实践考量与提示工程** 上下文学习还具有便利性的实际优势：我们可以在云端商业运行的 LLM 上执行 ICL，通过智能手机即可操作，而无需经历寻找计算机来训练大型模型的困难。

尽管提示为 LLM 提供了用户友好的界面，但上下文学习的成功往往对提示的表述方式或所提供示例的变化非常敏感。提示学习是脆弱的，一个新的领域叫做**提示工程（prompt engineering）**应运而生，帮助人类用户学习如何让 LLM 做我们想让它做的事 [Radford et al., 2019, Wei et al., 2022a, Giray, 2023, Sahoo et al., 2024]。

在大多数 LLM 中，上下文窗口会配有隐藏提示，即**系统提示（system prompts）**，用于为模型指定特定角色、防止使用不当用语，以及在聊天机器人中保存先前搜索结果的简短历史，以实现更自然流畅的对话。

上下文学习催生了大量后续研究。其中一个领域是多步推理，这也是本章的主题。推理曾经是 LLM 表现较差的领域。例如，LLM 在简单的数学练习上就会失败。为了更好地理解这个应用领域，我们将介绍一些推理基准测试。然后我们将讨论一种上下文学习方法，它极大地提升了 LLM 的推理性能。

### 6.1.2 多步推理基准测试

人工智能的进展通过基准测试来衡量。LLM 多步推理的研究从简单的（小学）数学应用题开始。专门为了研究这类简单推理，GSM8K 基准测试被构建 [Cobbe et al., 2021]。GSM8K 的创建旨在提供高质量、高多样性且难度适中的自然语言问题。它包含 8500 个人类编写的数学问题和解答。在思维链被引入之前（见下一节），语言模型在这个数据集上难以取得良好的性能。以下是一个典型数学应用题的示例：

*问题：* Romeo 每周烤 4 盘饼干，每盘两打。如果这些饼干平均分给 16 个人，每个人吃多少块饼干？

*答案：* $4 \times 2 \times 12 / 16 = 6$。

GSM8K 基准测试虽然对我们来说可能看起来很简单，但对 LLM 来说却颇具难度。当它被引入时，当时最先进的 LLM GPT-3-175B 仅达到了约 15% 的较低准确率 [Wei et al., 2022b]。其他类似的数学应用题基准测试包括：SVAMP 变化结构基准测试 [Patel et al., 2021]、多样化数学问题数据集 ASDiv [Miao et al., 2021]、代数应用题数据集 AQuA [Ling et al., 2017]，以及 MAWPS 基准测试 [Koncel-Kedziorski et al., 2016]。

后来，其他任务的基准测试也被引入，以评估 LLM 在其他推理领域的能力。例如，针对高等数学问题（AIME [Codeforces, 2024]）、计算机代码理解（Spider [Yu et al., 2018]）、跨编码（将一种编程语言翻译成另一种）[Roziere et al., 2020]、机器人运动（Alfworld [Shridhar et al., 2020]、厨房任务 [Ahn et al., 2022]）、谜题求解（24 点游戏 [Yao et al., 2024]、创意写作 [Yao et al., 2024]）、棋盘游戏（将杀问题 [Yang et al., 2024]、MineCraft [Fan et al., 2022]）以及网页导航（WebShop [Yao et al., 2022a]）等基准测试相继被开发出来。进一步的相关基准测试研究也聚焦于游戏和规划问题 [Ruoss et al., 2024, Paglieri et al., 2025, Wen et al., 2025a]。

基准测试的目标是能够清晰地比较不同方法的性能。然而，直接比较不同的基准测试结果可能很困难，因为实验进行方式可能存在差异。参见 Kamoi et al. [2024], Shojaee et al. [2025] 关于 LLM 推理基准测试挑战的批判性讨论。

### 6.1.3 思维链提示

大约 2022 年前后，当时的常规 LLM 在简单的数学应用题上表现不佳。有趣的是，第 4 章中提到的通过扩大 LLM 规模来提升性能的标准方法并没有解决这个问题 [Rae et al., 2021]。这个问题似乎在本质上具有某种根本性，研究人员开始寻找不同的方法。

LLM 的架构是基于 Transformer 的解码器。给定某个输入，它被设计为生成单个 token。LLM 是下一个 token 预测器。当我们提示这样的解码器生成答案时，它会按照指令行事：快速提供一个答案——任何答案。但这不是人类在数学推理问题中寻求答案的方式，我们会将问题分解为一系列步骤来求解（$4 \times 2 \times 12 / 16 = 6$）。因此，对于 LLM，我们应该做的是提示它遵循一个精心选择的中间步骤序列，逐步回答，从而推导出最终答案——就像学生在学校被教导将复杂问题分解为更小的步骤，并在回答问题时提供推理步骤一样——*不要只告诉我答案，而是告诉我你是如何得出答案的*。

儿童在学校被教导在解决数学问题时将大问题分解为一系列小步骤。同样，我们应该引导语言模型显式地生成这样的中间步骤，然后组合结果。LLM 应该提供一个包含中间步骤的答案，从而得到正确的结果。因此，我们的少样本提示应该包含中间推理步骤的示例，而不仅仅是最终答案的示例。

这个问题被 Wei et al. [2022b] 等人研究，他们引入了**思维链（Chain of Thought）**方法。图 6.1 展示了该方法的工作原理，以及由此启发的相关方法。

![图 6.1 不同的思维链（CoT）提示技术](/figures/chain_of_thought_techniques.png)

*图 6.1：不同的思维链（CoT）提示技术 [Wei et al., 2022b, Kojima et al., 2022, Gao et al., 2023, Plaat et al., 2025]。上方为提示，下方为答案。*

指导 LLM 生成中间步骤的方法是手动编写一个提示，由特定的推理步骤来回答任务（例如，计算容器中有多少球，或饼被切成了多少块）。确实，当 Wei et al. [2022b] 尝试这种方法，并提示 LLM 将问题中的信息重新表述为答案中的中间推理步骤时，LLM 的表现远优于被提示生成单一答案时的表现。思维链论文中的示例如图 6.1 所示。当看到更长的示例提示时，LLM 在回答问题时会遵循更长的示例（少样本 CoT）。在 GSM8K 上，思维链方法的准确率从 16% 大幅提升至 47%。

当被提示时，LLM 能够遵循逐步指令的想法引起了极大的关注，并开启了 LLM 多步推理的进一步研究。思维链（CoT）此后成为 LLM 中的标准提示方法。

在原始论文中，提示是由研究人员针对各类问题手动编写的。Kojima et al. [2022] 更进一步。他们表明，添加一个与任务无关的句子（*Let's think step by step*，让我们一步一步思考）也能显著提高许多问题的性能。由于这段文本不包含与问题相关的元素，它作为一种零样本学习形式。图 6.1 比较了这些方法（第二列和第三列）。实验进一步表明，通过这一补充，在其他推理基准测试上也取得了显著的性能提升，包括算术推理、符号推理和逻辑推理（当同时包含自一致性方法时，在 GSM8K 上达到 70% 的准确率，使用更新的 PaLM LLM [Wang et al., 2022]）。

思维链的想法本身受到 Scratchpad [Nye et al., 2021]、其他早期为算术推理生成自然语言步骤的工作 [Ling et al., 2017, Cobbe et al., 2021]，以及使用形式语言进行推理的工作 [Roy and Roth, 2016, Chiang and Chen, 2018, Amini et al., 2019, Chen et al., 2019] 的启发。

#### 6.1.3.1 自我评估

LLM 并不完美，结果中会出现错误。当生成多个推理步骤时，错误会累积。为了防止错误失控，我们应该格外关注结果的评估。我们现在将回顾减少错误累积的方法，可以通过检查模型或评估中间推理步骤来实现。

当 LLM 被提示执行 CoT 推理时，它们执行一系列步骤。执行多个步骤使它们对错误敏感，容易受到错误累积的影响 [Weng et al., 2022, Xiao et al., 2023]。已经开发了多种方法来防止错误累积。一种方法是创建一个新模型来单独评估结果。Weng et al. [2022] 提出了一种自动化方法，使用同一 LLM 进行评估，称为**自验证（self verification）**。LLM 被提示使用思维链推理链的结论作为解决原始问题的条件，然后比较答案，回到原始问题。LLM 被给予其自身结论的各种变体，并被指示选择与原始问题相似度最高的一个。

一种流行的相关方法是**自一致性（Self Consistency）**[Wang et al., 2022]。自一致性是一种集成方法（一种众所周知的机器学习技术，通过运行多个较弱的学习器来构建一个强学习器 [Sagi and Rokach, 2018, Breiman, 2001]）。传统上，LLM 查询的答案是通过贪心地遵循具有最高 logit 值的路径从解码器网络中提取的。在自一致性中，贪心单路径解码被替换为对更广泛路径样本的多数投票。通过采样多样的推理路径、评估它们，并选择其中最一致的答案，自一致性有效地要求 LLM 对同一查询执行多次，并取 Transformer 模型内部解码路径的多数投票结果。自一致性之所以有效，是因为复杂的推理问题通常有不同的推理路径可以导向正确答案。图 6.2 提供了该方法的一个示例。

![图 6.2 自一致性方法，展示多数投票](/figures/self_consistency.png)

*图 6.2：自一致性（改编自 [Wang et al., 2022]），展示多数投票。*

自一致性已在算术推理、常识推理和符号推理任务上进行了评估，使用了多种 LLM，包括 GPT-3。自一致性通常会将思维链的性能进一步提升 10-20 个百分点。自一致性在现代 LLM 中经常与思维链结合使用。

#### 6.1.3.2 用于验证的代码生成

提高推理步骤序列准确性的另一种方法是从自然语言切换到形式语言。形式语言的优势在于它比自然语言的歧义更少。例如包括计算机语言（如 Python）或数学逻辑。

LLM 在从自然语言提示生成计算机代码方面已经相当成功。Chen et al. [2021] 引入了 Codex，一个在 GitHub 仓库中公开可用的代码上训练的 GPT 模型。Codex 能够从自然语言描述（如注释字符串）中生成正确的程序。随后，使用形式语言进行推理成为一种流行的方法。许多方法以 Python 生成推理步骤，以便代码可以被编译器、调试器或解释器评估。

人类程序员在编写代码时，通常遵循编写一些代码、编译和执行它以查找错误、然后使用反馈来改进代码的循环。这种方法在**自调试（self debugging）**[Chen et al., 2023] 中得到了遵循。它遵循代码生成、代码执行和代码解释的相同步骤。自调试能够通过调查执行结果来识别自己代码中的错误，并且还能以自然语言提供生成代码的解释。

另一种方法——**程序辅助语言（Program Aided Language）**[Gao et al., 2023]——使用 LLM 生成 Python，然后使用解释器来评估结果。在这种方法中，问题被转化为小段 Python 代码，然后由解释器执行来解决问题。图 6.1（第四列）展示了程序辅助语言方法。当推理步骤的评估被卸载到 Python 解释器时，将自然语言问题分解为可执行代码步骤仍然是 LLM 的唯一任务。Gao et al. [2023] 提供了大量的实验证据，展示了神经 LLM 和符号解释器之间的协同效应。实验在 13 个数学、符号和算法推理任务上执行，取得了比当时大得多的模型更准确的结果（例如，程序辅助语言在 GSM8K 上报告了 72%，在 Penguins 上报告了 93%）。

#### 6.1.3.3 进化代码生成提示

关于形式语言验证的工作引出了多项研究，这些研究自动生成经过调整的工作代码来解决特定问题，无需人工反馈。Romera-Paredes et al. [2024] 引入了 FunSearch，一种整合形式方法和 LLM 以增强数学推理和代码生成的方法。FunSearch 使用遗传方法，包含多个候选解（程序）种群，根据问题规范使用函数进行评估。在评估从起始提示生成的程序后，以迭代方式创建新的提示，结合根据评估分数排序的采样程序的选择，并要求 LLM 生成新程序。

另一项工作利用进化计算方法来生成和优化进化算法 [van Stein and Back, 2024]。这种方法 LLaMEA（大型语言模型进化算法）利用 LLM 来设计和优化进化算法。该方法使用 LLM 生成初始算法结构，然后通过变异和选择进行改进。在黑箱优化基准（BBOB）[Hansen and Ros, 2010] 上报告了 11 个百分点的准确率提升。

## 6.2 自我反思与状态

上下文学习已成为一种强大的新型少样本学习方法。当我们的少样本示例指定了推理步骤时，我们可以进一步提升 LLM 的能力。在本节中，我们将考察上下文学习的一些局限性，以及扩展这些限制的方法。我们将首先讨论状态和记忆的问题。我们将研究如何在 LLM 的独立调用之间传递状态，考察长上下文窗口，以及探讨 LLM 是否擅长解决需要操纵状态的问题。

### 6.2.1 LLM 是无记忆的函数

上下文少样本学习利用了 LLM 检索知识的能力，以提示为条件。提供指令和示例后，Transformer 架构在其庞大的 $(K, V)$ 参数模型中找到答案（下一个 token）。通过思维链提示，LLM 以提示中指定的少样本推理步骤为条件。上下文学习以函数方式使用 LLM，其中所有输入都在提示中提供给 LLM。模型 $f$ 为输入提示 $p$ 找到答案 $a$：

$$f(p) \rightarrow a$$

原则上，LLM 在调用之间不保留信息（模型参数保持不变，也没有带历史的全局变量）。如果我们希望细化请求，并希望将状态信息从上一次调用传递到下一次，那么所有这些状态必须由用户在新提示 $p'$ 中指定。模型本身已经忘记了之前的所有答案。

对于聊天机器人来说，在每个新问题中重复整个对话历史将是一种繁琐且不自然的对话方式。在人类对话中，我们的对话伙伴会记住最后说过的话，而不需要我们显式地重复他们最后的句子（尽管在采访政客时，记者有时会使用这种方法来试图让他们保持话题）。商业聊天机器人部分通过使用系统提示来克服这个问题，在不可见的情况下将上一次 LLM 调用的输出提供给新 LLM 查询的提示。然而，原则仍然是：LLM 擅长为提示找到关联性的下一个 token 答案，但完全不擅长记忆答案和操纵变量状态——就像我们在通用计算机编程语言中所知道的那样。由于没有参数被改变，LLM 在调用之间不记忆上下文状态。

### 6.2.2 检索增强与长上下文窗口

LLM 的记忆问题更为深层。查询的所有信息必须在上下文窗口中指定。这个上下文窗口的大小是有限的，从根本上限制了可以为查询传递给 LLM 的信息量。当需要总结大段文本（如一本书）时，这种限制就成了问题。此外，我们将在第 20.2.1 节中讨论上下文**强化**学习方法，这些方法通过在上下文窗口中存储完整的回合历史来工作。简而言之，需要方法来向 LLM 传递更多信息。

最早扩展推理时信息量的方法之一是**检索增强生成 AI（Retrieval Augmentation for Generative AI, RAG）**。RAG 让 LLM 调用外部数据，如企业数据库或维基百科 [Lewis et al., 2020]。RAG 的作用还在于减少事实性幻觉并提供对时间敏感信息的访问，如金融或物流数据。RAG 将在第 12 章中讨论。

为了向模型传递更长的文本，已经开发了具有更长上下文窗口的 LLM。使用标准 Transformer 架构，计算需求随上下文窗口大小呈二次方增长，线性架构正在被开发 [Ren et al., 2024]。另一种解决方案是压缩上下文窗口中的信息，例如使用语义压缩 [Fei et al., 2024]、对信息进行分块 [Wang et al., 2023, Zhou et al., 2025]，或使用递归方法 [Zhang et al., 2025]。为 LLM 设计新型记忆架构是一个活跃的研究领域 [Yan et al., 2025]。

### 6.2.3 LLM 与有状态问题

LLM 在解决需要管理状态的问题上表现不佳 [Wong et al., 2025]。例如在规划问题中，当前状态必须被准确记住，即使在如图 6.3 所示的简单棋盘游戏中也是如此。LLM 倾向于混淆状态，并提供听起来合理的答案——这些答案对于其训练语料中见过的游戏可能是正确的，但对于当前的实际棋盘状态却是错误的 [Paglieri et al., 2025, Ruoss et al., 2024]。

已经尝试了许多方法来改善有状态的推理，通常受到强化学习和规划算法的启发 [Wong et al., 2026]。为了了解 LLM 如何解决这些有状态问题，我们讨论 LLM 的无记忆特性如何使它们遭受所谓的**知行差距（knowing-doing gap）**问题。其他高级方法已被开发出来以使 LLM 更好地处理有状态问题。第 20 章将讨论这些高级方法。

**知行差距** 除了在 LLM 调用**之间**缺乏状态外，在 LLM 对某些任务进行**内部**执行时还存在另一个与记忆相关的问题。这个问题被称为**知行差距（knowing-doing gap）**。这一差距描述了一个有趣的现象：LLM 能够生成正确的文本来描述如何解决一个问题，甚至是正确的算法，但无法正确执行这个算法 [Paglieri et al., 2025]。当你问 LLM 如何解决某个问题时，它能迅速提供可执行的 Python 代码形式的正确算法。但当随后要求它实际解决这个问题时，LLM 并没有正确遵循它刚刚生成的算法。往往，错误开始出现在它生成的算法中变量的状态变化之间 [Paglieri et al., 2025, Ruoss et al., 2024]。需要注意的是，忠实地逐步执行算法代码、跟踪寄存器中的值，完全不是 LLM 中基于注意力的 Transformer 被设计来做的事情——它们被设计为通过一种关联记忆的形式来模拟自然语言处理 [La Malfa et al., 2024]。

> *注：人类大脑有时也有同样的问题：我们可以轻松描述长除法的算法，但当被要求计算 $12345/42$ 时，我们可能会犯错——计算机擅长这个，但人类不行，LLM 也不行。*

除了知行差距之外，还有另一个状态管理问题。提示 LLM 与自己下棋盘游戏的前几步可能会显示一盘棋子在走步之间神奇地（消失或）出现的对局。模型无法认识到它所执行的走法在某些情况下可能是好的，但并不适合当前的棋盘位置，甚至还会以聊天式的对话风格为这些错误的走法附上听起来合理的理由。LLM 难以可靠地管理变量从一个值到另一个值的状态转换。单个值往往被遗忘或混淆。可以在提示中插入额外文本来指示模型在进行下一步之前仔细跟踪变量的值 [La Malfa et al., 2024]，但这是一个繁琐且容易出错的解决方案。

知行差距和棋子消失问题都可以通过调用外部解释器来执行 LLM 生成的算法来规避。商业聊天机器人有时会采用这种策略。这是一个聪明的、实用的解决方案，因为除了能够正确执行 Python 代码外，Python 解释器的执行效率也比 LLM 更高。第 20 章将讨论其他解决 Transformer 架构中状态和记忆问题的方法。

### 6.2.4 用于提示改进的智能体框架

除了借助外部执行生成的代码之外，还开发了其他方法来处理记忆和状态。在本节中，我们将进入智能体领域，引入小型外部算法来显式管理状态和提示。这样的算法被称为**框架（harness）**。框架还可以以不同角色调用同一个 LLM，为每个角色使用不同的提示，例如用于**生成**或**评估**状态。

我们从基于搜索算法的提示管理开始讨论。当 LLM 被以不同角色调用时，例如批评（评估）自己刚刚生成的表现，可以说 LLM 在执行**自我反思（self-reflection）**。这个略带拟人化的术语在文献中经常被用于这些方法。确切地说是什么（而非谁）在进行自我反思——是 LLM 还是智能体框架——是一个值得讨论的问题。

#### 6.2.4.1 基于搜索的提示优化

我们现在将讨论基于搜索的推理时决策方法。这些是超越思维链的上下文学习方法。思维链探索单线推理步骤，其中每一步只有一个后续步骤。基于搜索的方法在每一步探索多个选项，创建一个可能性树。

当我们希望检查一个可能推理步骤的树时，我们需要一种方法来跟踪我们已经看到了哪些步骤、到目前为止最好的答案是什么，以及哪些步骤还需要进一步检查。正如我们所见，LLM 并不特别擅长跟踪状态，而传统的计算机算法（如小段 Python 代码）则擅长。这样的算法将问题分解为搜索树，其中生成多个替代步骤，可以向未来搜索多步（见图 6.6）。算法将 LLM 作为子程序调用，提示它执行请求的任务，如动作选择和奖励评估。然后，算法可以执行回溯，允许尝试替代步骤。这个控制算法在 LLM 外部。它包裹着 LLM，跟踪状态，管理提示，将其与外部世界隔离（并保护外部世界不受 LLM 搞乱状态的影响）。这个控制算法被称为**框架（harness）**。

我们从深度优先搜索和广度优先搜索 [Cormen et al., 2022] 开始讨论控制策略。**思维树（Tree of Thoughts）**[Yao et al., 2024] 使用广度优先搜索或深度优先搜索来动态跟踪不同的推理步骤。思维树中的生成（红色）和评估（绿色）部分都通过提示 LLM 来执行，如图 6.4 所示。两个 LLM 提示与外部控制一起，允许对推理步骤空间进行系统探索，执行前瞻和回溯。

思维树（ToT）已被用于基于规划的谜题，如 24 点游戏。在这个游戏中，给出 4 个数字，任务是使用数字之间的算术运算符（$+-*/$）得到数字 24。例如，对于数字 4 9 10 13，一个解是 $(10-4) \times (13-9) = 24$。思维树首先生成一个位置，使用**提议**提示：输入 4 9 10 13；可能的下一步：模型通过生成可能的下一步思考来回答。然后使用包含思维链示例的评估提示由模型进行评估。图 6.5 展示了原始论文中一个可能的提示序列。

#### 6.2.4.2 自我反思

许多方法被设计出来以多种角色使用 LLM。这类方法通常被称为自我反思方法。LLM 不仅用于评估提示，还用于生成新的推理步骤，并经常对其进行改进。自我反思领域还很年轻，新方法不断被开发出来。我们将介绍四种方法：自我改进（Self Refine）、ReAct、Reflexion 和思维缓冲（Buffer of Thoughts）。这些方法以不同的方式使用 LLM，采用受强化学习启发的方案让 LLM 改进自身。

**自我改进（Self Refine）** 第一种方法是自我改进 [Madaan et al., 2023]。这种方法旨在通过反馈改进答案。LLM 生成初始输出并为其答案提供反馈，使用 LLM 迭代地改进自身。LLM 因此被用于改进自己的答案，如图 6.7 所示。

![图 6.7 自我改进架构](/figures/self_refine.png)

*图 6.7：自我改进架构 [Madaan et al., 2023]。*

自我改进以三种方式提示 LLM：（1）初始生成，（2）反馈，以及（3）改进，遵循贪心推理链。据报道，自我改进在对话响应生成、代码优化和约束生成等基准测试上显著优于常规思维链。这种方法确实遵循线性的、贪心的推理链，在状态中只尝试单个后续步骤（它不像 ToT 那样探索树）。

**ReAct** 将贪心方法泛化，我们可以使用 LLM 检查每个状态的多个选项。一个结合了强化学习和 LLM 的显著方法是 ReAct [Yao et al., 2022b]。ReAct 使用思维链提示学习作为强化学习框架的一部分，该框架还使用外部知识源（维基百科）和微调；用于减少错误、接地和减少幻觉。该框架允许手写提示。在两个交互式决策基准测试（Alfworld 和 WebShop）上，ReAct 分别以 34% 和 10% 的绝对成功率超越了模仿学习和强化学习方法。

**Reflexion** ReAct 的工作得到了进一步发展。Reflexion [Shinn et al., 2024] 创建了通过反思失败来学习并增强其结果的 AI 智能体，灵感来自人类这样做的方式。Reflexion 为 LLM 使用三个提示：执行者（actor）、评估者（evaluator）和反思者（reflector）。Reflexion 框架在 LLM 调用之间纳入显式记忆。对于轨迹生成，它有短期记忆；对于存储经验信息，它有长期记忆。这种方法使用外部算法中的记忆解决了常规 LLM 的状态管理问题。

![图 6.8 Reflexion 架构](/figures/reflexion.png)

*图 6.8：Reflexion 架构 [Shinn et al., 2024]，展示了与强化学习的智能体/环境结构的密切相似性。*

Reflexion 的工作方式如下：（1）执行者模型生成文本和动作，（2）评估者模型对执行者产生的输出进行评分，（3）自我反思模型生成语言强化线索以帮助执行者自我改进（见图 6.8）。对于执行者，可以使用思维链和 ReAct。Reflexion 已在决策、推理和编码任务上进行了评估。据报道改进了 10-20 个百分点 [Shinn et al., 2024]。

**思维缓冲（Buffer of Thoughts）** 另一种方法是思维缓冲 [Yang et al., 2024]，它朝着元推理 [Gao et al., 2024] 迈进了一步。它引入了一个存储高级**思维模板（thought-templates）**的元缓冲区。思维模板从各种任务中派生。思维缓冲使用问题蒸馏器，将从不同问题中蒸馏出的高级思维存储在元缓冲区中，该缓冲区主动管理容量。图 6.9 将思维缓冲方法与思维链和思维树等其他方法进行了比较。思维缓冲在 24 点游戏（提升 11%）和将杀（提升 51%）等谜题中优于其他方法。思维模板与元认知（关于思考的思考）[Didolkar et al., 2024] 相关。

![图 6.9 思维缓冲方法](/figures/buffer_of_thoughts.png)

*图 6.9：思维缓冲 [Yang et al., 2024]。*

**批评与提示敏感性** 自我反思的概念并非没有陷阱和批评。首先，要求模型改进其结果的基本想法引发了一个问题：为什么模型不在第一次就给出更好的答案。其次，Huang et al. [2023], Shojaee et al. [2025] 的研究发现了一些研究中的方法论问题，例如使用揭示答案的数据标签、无意中比初始提示透露更多信息的第二次改进提示，以及在同一 LLM 上同时使用智能体和环境。在一项可重复性研究中，性能没有超过带有自一致性的思维链 [Huang et al., 2023]。

LLM 对提示中问题的表述方式非常敏感。自我反思仍然是一个年轻且活跃的研究领域，前提很有吸引力，但存在许多未解问题。我们所介绍的方法可能需要进行大量 LLM 调用，这可能变得昂贵且缓慢。为你的问题找到最优方法可能需要大量实验。在第 10 章中，我们将讨论一个实际案例研究，在那里我们将获得自我反思方法的实践经验。请记住前面的批评。

#### 6.2.4.3 可验证奖励的强化学习

本章的重点是上下文学习。上下文学习发生在推理时，不训练或改变参数。微调发生在训练时，确实改变模型参数。然而在本节中，我们将简要讨论微调与上下文学习的混合——我们将混合训练和推理。

**可验证奖励的强化学习（Reinforcement Learning with Verifiable Rewards, RLVR）**指的是一种算法方法，用于在具有可验证结果的任务（如数学问题求解和指令遵循）上训练语言模型。特别是对于推理问题，如数学应用题和编码，推理时的思维链结果已被发现在用于微调时能显著改进模型。RLVR 是对人类反馈强化学习（RLHF）的改进，消除了对人工反馈的需求。在许多领域（如数学），存在简单的函数来检查答案是否正确，无需人工反馈。RLVR 利用现有的 RLHF 目标，但用验证函数替代奖励模型。RLVR 从策略模型中针对一组提示采样完成，并使用确定性函数验证其正确性。如果正确，奖励为正，否则为 0。然后使用该奖励通过 PPO [Schulman et al., 2017]（一种标准强化学习算法）进行训练，如同 RLHF 一样。

一个具有影响力的此类方法是在 DeepSeek-R1 的开发中提出的 [Guo et al., 2025]。该方法通过强调模型自生成的推理步骤来区别于外部推理方法。它通过强化学习学习这些步骤，将数据生成和训练整合在一个循环中。DeepSeek 的方法论降低了训练 LLM 所需的监督数据量，利用强化学习使模型能够自主发展推理技能。通过从基础模型开始并应用强化学习，系统识别并强化有效的推理模式。DeepSeek 使用**组相对策略优化（Group Relative Policy Optimization, GRPO）**，它通过基于组的评分来计算优势 [Shao et al., 2024]。

DeepSeek 方法的关键特征之一是在微调过程中出现了复杂的推理行为，如反思和探索替代问题解决方法 [Mercer et al., 2025]。这些行为是自发的，源于模型与强化学习环境的交互，而非预先编程的，也不需要外部自我反思循环。例如，DeepSeek-R1-Zero 学会通过重新评估其初始方法，将更多的思考时间分配给问题。这种**学习推理**的自主方法可能带来更稳定和适应性更强的推理 LLM。

GRPO 成功的关键在于其聚焦于存在可验证奖励的应用，使强化学习方法得以使用。对可验证奖励的关注相当成功，可验证奖励的强化学习（RLVR）方法经常用于 LLM 的微调 [Lambert et al., 2024]。RLVR 方法（如 GRPO）通常动态使用，其中推理时的思维链查询用于回答训练集中的查询以微调模型。因此，测试时推理被用于微调。

DeepSeek [Guo et al., 2025] 令人印象深刻的结果使 GRPO [Shao et al., 2024] 和 RLVR [Lambert et al., 2024, Guo et al., 2025, Wen et al., 2025b, Yue et al., 2025] 成为高度流行的微调方法。

## 6.3 结语

在前面的篇幅中，我们看到了如何提升语言模型的推理能力。最著名的方法是思维链，这是一种提示工程方法，它向 LLM 展示在回答问题时提供多步推理，就像我们在学校被教导如何解数学练习一样。更复杂的提示改进算法已被引入，从深度优先搜索、自我反思到推理时强化学习方法。像 RLVR 这样的高级训练方法将推理结果与微调相结合，取得了强大的训练效果。

### 6.3.1 脆弱性

我们讨论了许多不同的算法方法来创建智能体框架。之所以有这么多方法，有多个原因。首先，智能体 LLM 领域仍然很年轻，存在许多挑战，导致许多新的解决方案。其次，这些方法相当脆弱。提示中的微小变化——这里或那里的一个逗号——有时决定了一个方法是否有效。超参数的微小变化，如模型的温度，甚至使用不同的随机数生成器种子，都可能产生很大的影响。智能体框架的记忆管理方法的改变，或使用不同的 LLM，都可能对性能产生重大影响。

这可能让人感到不满意。确实，这个领域还很年轻，方法需要几年时间才能稳定下来。在你的实验中，你应该始终记住进行多次运行，使用不同的种子、不同的模型和不同的超参数设置。这将帮助你更好地理解你的解决方案在不同条件下如何工作。

### 6.3.2 思考，快与慢

在本章结束时，我们将在更广泛的视角下讨论 LLM 中的推理。在 AI 的历史中，可以看到两种方法或思想流派：符号 AI 和连接主义 AI。符号 AI 大致对应于这样的理念：智能最好被建模为通过逻辑规则操纵符号。连接主义 AI 研究智能是否自发地从连接元素之间的交互中涌现（无论是神经元、细胞、蚂蚁、人类还是机器人）。符号 AI 借鉴数学，连接主义 AI 借鉴生物学。正如我们在第 2.3 节中已经看到的，两个学派都发展出了有用的方法，都取得了重要的成功（如搜索算法和推理，或深度学习和 LLM）。

2011 年，Daniel Kahneman 出版了《思考，快与慢》一书，其中使用**系统 1**和**系统 2**的术语来区分人类的直觉、快速思考与审慎、缓慢思考 [Kahneman, 2011]。这些术语在人工智能中变得流行，其中快速思考与关联查找相关联，缓慢思考与多步推理相关联。

在推理时，零样本 LLM 进行快速思考（系统 1 思维）。推理时的逐步方法（通过更长的提示或智能体框架）执行审慎的缓慢思考（系统 2 思维）。LLM 基于连接主义 AI 传统（系统 1）。在推理时使用工具增强了 LLM 部分，加入了来自符号 AI 传统（系统 2）的知识检索或处理工具。

我们应该注意到，虽然研究人员有时会将 LLM 及其能力拟人化，但 LLM 仅仅执行下一个 token 预测。LLM 远非人类。通过生成更多 token 来形成答案（逐步推理），从提示到最终答案的 token 路径变得更长。这之所以更经常导致正确答案，可能是因为它朝着答案方向采取了更小的步骤，使正确答案在每一步之间变得更加可能——而不是因为它类似于人类被教导解决问题的方式。

推理是缩小概率范围，使正确答案更有可能被生成，这与人类认知相关的解释无关 [Guo et al., 2025]。

### 6.3.3 结论

在本章中，我们讨论了 LLM 如何通过下一个 token 预测来解决语言任务，以及解决需要多步推理的任务。我们讨论了管理复杂推理结构的方法。大多数方法是上下文方法，高效且易于使用，因为引导推理的提示对用户是可读的。我们介绍了智能体框架在提示改进和记忆管理中的作用。我们还涉及了不仅用于语言部分，还用于整合多步推理的预训练和微调方法。这些方法因此训练模型进行决策，超越了语言模型中纯粹的下一个 token 预测。在创建更丰富的模型方面已有大量活动，将视觉推理、决策制定和行动添加为 LLM 的组成部分。在下一章中，我们将更深入地研究这些预训练和微调的多模态模型。
