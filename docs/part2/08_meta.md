# 元学习

> **本章学习目标**
>
> 本章将介绍元学习（Metalearning）。具体而言，你将能够：
> - 识别 LLM 流水线中使用的不同**层次**的学习；
> - 理解上下文学习（In-context learning）、**少样本学习**（Few-shot learning）与元学习之间的联系；
> - 构建一个由**内层**学习循环和**外层**学习循环组成的元学习系统；
> - 认识移动目标问题（Moving-target problem）：为什么在动态元学习系统中实现**稳定**学习是具有挑战性的。

## 8.1 为什么需要元学习？

如前所述，自反思 LLM 方法非常强大，但使训练过程收敛可能是一项挑战。在智能体 LLM（Agentic LLM）中，学习发生在多个层次上，有时甚至同时发生。在机器学习中，在多个层次上进行学习的算法被称为执行元学习。元学习通常被描述为**学会学习**（learning to learn），例如，学习哪种提示（prompt）对某项任务更有效。元学习可以是一个强大的概念，但有时不同的学习层次会相互干扰，导致学习停滞。

为了帮助我们理解为什么 LLM 的多层次学习算法有时不起作用，我们将深入研究元学习。在本章中，我们将讨论如何提高动态、反馈丰富的元学习方法的稳定性。

元学习这一术语用于多层次学习算法。元学习算法学会学习，从而快速解决模型未曾训练过的新的、未见过的任务样本。

### 8.1.1 深度学习是缓慢的

元学习在机器学习中有着悠久的历史（参见例如 Schmidhuber [1987]，Hospedales et al. [2021]，Huisman et al. [2021]）。它的灵感来源于人类学习，因为人类被认为能够学习如何学习。其发展的另一个原因是速度。问题在于常规深度学习是缓慢的。典型深度学习任务的神经网络规模庞大，拥有数百万甚至数十亿参数，训练它们需要大规模数据集，通常包含数百万样本。从零开始训练网络的训练时间很长，从数小时到数月不等，只有在使用特殊的并行硬件（GPU）之后，深度学习才取得了成功 [Krizhevsky et al., 2012]。此时，研究人员开始梦想少样本学习——一种仅通过少量样本训练就能达到高准确率的方法。

### 8.1.2 实现少样本学习

在机器学习中，某些算法比其他算法更适合特定类型的问题。此外，大多数训练算法包含可以调优以提升性能的元素，如学习率（learning rate）、动量（momentum）、参数的初始化方案，或者对于多层次算法而言，甚至是底层训练算法的选择。这些元素被称为**超参数**（hyperparameters），它们控制着算法的学习方式。我们能够学习它们吗？不同类型的问题需要不同的超参数设置。例如，对于平滑的数据集，较高的学习率或局部搜索算法可能效果良好；但对于峰值分布的数据集，较低的学习率或全局搜索算法效果更好。关键在于，机器学习中最佳的超参数配置取决于待解决的任务，而且至关重要的是，这种配置是可以被学习到的。为不同任务学习此类算法超参数的过程被称为**元学习**。（相比之下，模型常规参数的学习现在被称为**基础学习**（base learning）。）元学习的目标是创建能更快学习特定任务的算法。与其使用一个未针对任务调整的通用算法从零开始，我们应该使用一个其超参数首先匹配待解决任务类型的学习算法。元学习的方法是首先从一组相关任务中学习如何配置学习算法，学会更快地学习某一组任务。当我们学到了这种自适应算法的超参数配置后，我们可能希望实现少样本训练：仅通过少量样本进行训练，同时在新测试任务的样本上仍然获得高准确率。元学习通过不从零开始而是从相关知识开始训练来实现少样本学习。元学习由一个（超参数）训练循环包裹在一个（基础）训练循环之外组成。在经典（非神经网络）机器学习中，常见的超参数包括学习率或算法选择，即在训练任务上测试不同的学习算法 [Brazdil et al., 2022]。在深度学习中，神经网络的权重初始化经常被使用 [Finn et al., 2017]。在智能体 LLM 中，我们也遇到了不同层次的学习（我们将在下一章继续讨论多层次学习）。研究元学习文献中的理论和见解对我们是有益的。

## 8.2 内层循环/外层循环

与任何监督学习方法一样，元学习包括（1）**元训练**（meta-train）阶段，在各种相关任务上进行训练；（2）**元测试**（meta-test）阶段，在新的、未见过的任务上进行测试，以观察其对新**任务**的泛化能力。目标是通过学习训练算法的超参数设置来提高泛化能力，使其在广泛的各种训练任务上表现良好。

模型参数的训练过程通过一个优化循环来实现，其中使用损失函数（loss function）计算训练样本与当前模型估计之间的差异。训练算法循环遍历数据集，每次调整模型参数，目标是最小化损失之和。

学会学习的概念由两个循环组成：一个**内层训练循环**（inner training loop），用于优化模型参数；一个**外层训练循环**（outer training loop），用于优化算法的超参数。内层循环在单个任务的**样本**上优化参数，外层循环在应用领域的**任务集**上优化超参数。

每个基础学习任务 $T_i$ 有一个数据集 $D_i$ 和一个学习目标——损失函数 $\mathcal{L}_i$。因此 $T_i = (D_i, \mathcal{L}_i)$。每个数据集由输入样本和标签对组成 $D_i = \{(x_j, y_j)\}$，并被划分为训练集和测试集 $D_i = \{D_{i,train}, D_{i,test}\}$。在每个训练数据集上估计一个参数化模型 $\hat{f}_{\theta_i}(D_{i,train})$，其损失函数为 $\mathcal{L}_i(\theta_i, D_{i,train})$。模型 $\hat{f}$ 通过一个由超参数集 $\omega$ 控制的算法来近似。具体的超参数因算法而异，但常见的超参数包括学习率 $\alpha$、初始参数 $\theta_0$ 和算法常数。

内层循环优化基础参数 $\theta$，外层循环优化超参数 $\omega$，以在基础任务集上找到最佳性能，并使用相应的测试数据：

$$\omega^\star = \arg\min_{\omega} \mathcal{L} \left( \arg\min_{\theta_i} \mathcal{L}_{\omega}(\theta_i, D_{i,train}) \right)$$

$$\underbrace{\hspace{3em}}_{\text{外层循环}} \quad \underbrace{\hspace{3em}}_{\text{内层循环}}$$

内层循环在任务 $T_i$ 的数据集 $D_i$ 内优化 $\theta_i$，外层循环跨任务和数据集优化 $\omega$。元优化的结果是一组最优超参数 $\omega^\star$。元学习完成后，我们获得了一组超参数（调优后的算法），它对于应用领域中的一组任务表现良好，我们可以假设它在新任务上仅经过少量样本训练后就能良好泛化，在未见样本的测试中获得高准确率。

**迁移学习** 元学习与迁移学习（Transfer learning）之间存在重要联系。迁移学习在单个任务上预训练神经网络，然后将权重迁移到快速微调阶段。因此，迁移学习可以被视为基于网络初始化的元学习方法的一次迭代：迁移学习就是只有一个基础学习任务的元学习。

## 8.3 LLM 与元学习

在 LLM 领域，我们在许多地方都遇到了元学习。一种常见的元学习方法是将模型参数初始化为先前学到的知识，以便它们在相关任务上能更快地训练。这就是迁移学习，它存在于每个标准的 LLM 训练流水线中——在预训练/微调（pretrain/finetune）阶段，我们获取预训练参数并针对特定任务进一步微调。元学习就是反复微调，而大语言模型正是一个实现机器学习主要目标——少样本学习——的元学习训练流水线的典型范例。

上下文学习是机器学习的重大突破之一 [Brown et al., 2020]。当我们转向智能体 LLM 时，少样本学习还出现在更多其他地方。我们将讨论静态和动态两种形式的元学习。在静态元学习中，内层循环中的权重不受其他循环的影响。在动态元学习中，权重会受到影响。

### 8.3.1 静态 LLM 元学习

我们首先回顾一些静态 LLM 元学习的例子。

#### 8.3.1.1 预训练流水线

常规的 LLM 训练流水线是一个精心设计的、多阶段迁移学习方案的良好示例。它实现了良好的零样本（zero-shot）性能，即能够基于预训练和微调后的知识准确回答许多常规查询——例如*莫扎特出生在哪里？*。流水线中的不同阶段是内层优化循环，而选择迁移哪些权重以及如何在后续阶段进行微调的人工选择，可以被视为外层循环的超参数选择。这是一种静态形式的元学习，因为权重一旦在某个阶段训练完成，就不会受到后续阶段训练结果的影响。权重在流水线的各阶段之间是稳定的。流水线是一个纯粹的顺序训练过程。

#### 8.3.1.2 上下文学习

超越零样本学习，上下文学习（In-context learning）是一种少样本学习形式，由用户提供少量训练样本，提示 LLM 推断出更好的答案。预训练模型是内层循环，提示中的样本引导外层循环。

这是一种静态形式的元学习，因为模型权重的值不受提示中样本的影响。

#### 8.3.1.3 思维链

常规上下文学习提供**事实**作为少样本示例；它关注内容。思维链（Chain of thought）提供**过程步骤**作为少样本示例；它关注过程。同样，预训练模型是内层循环，提示中的样本引导外层循环，而模型的权重是静态的。

#### 8.3.1.4 静态元学习是稳定的

常规 LLM 流水由按顺序运行的迁移学习阶段（内层循环）组成。一旦内层训练循环收敛，该阶段就不会再次运行。流水线是静态元学习的一种形式。（微调的结果不会被反馈回预训练器，预训练器也不会根据微调结果调整超参数重新运行。不同的训练阶段不会相互干扰。）

与静态元学习相反，还有动态元学习，其中不同的迭代会相互干扰。

### 8.3.2 动态 LLM 元学习

在智能体 LLM 中，使用了不同形式的动态元学习。在动态元学习中，各迭代并发运行，并可能对彼此的收敛过程产生不稳定影响。

在前面的章节中，我们讨论了自反思（Self-reflection）和 RLVR。这些方法中，内层循环可以被外层循环改变，一个内层循环的结果可能影响另一个内层循环。我们创造了一个移动的训练目标。这可能导致训练过程的不稳定发散。训练结果也可能表现得脆弱：它们对输入值或超参数的微小变化反应剧烈，例如不同的随机种子、不同的提示改写方式，甚至元学习过程本身长度的变化。此外，当同一模型被用于不同角色（如纠正和生成）时，基础 LLM 的幻觉倾向可能被放大。

让我们讨论智能体 LLM 中动态元学习的例子。

#### 8.3.2.1 自反思

在自反思（第 6.2.4.2 节）中，智能体框架（harness）执行提示管理，以不同角色调用 LLM，例如评估状态和完善答案。用元学习的术语来说，**模型**是内层训练循环，**框架**是外层循环。虽然模型本身是静态的，但它被以不同的提示调用，而模型的回答被框架用来生成新的提示。因此，提示结果（外层循环）开始相互干扰，并可能以非线性和非直觉的方式交互。此外，当同一模型被用于不同角色时，不完美之处（偏差、幻觉）可能被放大。

#### 8.3.2.2 RLVR

带可验证奖励的强化学习（RLVR，第 6.2.4.3 节）是代码和数学应用中流行的训练方案，其中推理时的推理结果被用于训练时的微调。用元学习的术语来说，**微调**是内层循环，推理时的**推理**是外层循环。RLVR 在内层循环中使用外层循环的结果，将推理结果反馈到训练阶段，混合了两种学习过程。应注意防止推理时的错误（被当作真实结果使用）在微调/推理循环中被放大。

## 8.4 稳定动态元学习

当内层/外层干扰欠阻尼（under-damped）时，就会发生不稳定训练。当这种情况发生时，内层循环和外层循环之间的振荡可能越来越大，而不是逐渐衰减。这个问题可以通过增加阻尼或解耦不同内层循环的运动时间尺度来缓解。例如，可以降低其中一个循环的学习率，或者使某些内层循环的参数比其他循环保持更长时间的稳定。

另一个想法是使用模型类型或大小的混合，如混合专家模型（Mixture-of-Experts）[Jiang et al., 2024]。学生/教师（student/teacher）设置有意为不同角色使用更强和更弱的模型。通过使用不同的模型，我们可能希望抑制幻觉和内层循环之间的干扰。

一般来说，当元学习表现异常时，我们应该致力于创造更多多样性，促进探索，并防止导致局部最优或发散训练的贪心行为。这些解决方案通常需要大量实验来建立对问题的直觉。调试智能体 LLM 可能具有挑战性。

## 8.5 总结

如我们所见，我们可以将 LLM 训练理解为一种元学习形式。常规 LLM 训练是一种迁移学习形式，而智能体 LLM 中使用的推理时推理和训练则运用了更多的元学习思想。虽然动态元学习方法（如自反思）是一个强大的概念，但应注意，内层循环和外层循环之间的干扰可能使训练过程不稳定。这可能在意料之外发生于此前表现正常的智能体中。

当我们在与世界交互的智能体中使用训练好的模型，并且该智能体也使用来自这种交互的反馈进行训练时，模型可以被视为基础学习者（内层循环），而与世界的交互可以被视为元学习者（外层循环）。前述关于流水线内元学习的所有注意事项同样适用于流水线外元学习。只不过现在，在与真实世界交互时，错误的后果可能更加严重。

在线机器学习的相关领域，如深度强化学习，也遭受着不稳定训练和移动目标问题的困扰。深度强化学习领域引入了许多稳定化技术，如经验回放缓冲区（replay buffers）和目标网络（target networks）[Mnih et al., 2015, Hessel et al., 2018]。这些方法通常试图解耦两个学习过程的周期性，通常通过减慢其中一个的速度来实现。类似的方法在层次推理模型（Hierarchical Reasoning Models, HRM）[Wang et al., 2025]中被引入。HRM 由两层元学习方法组成。在这里，学习也是通过以两种不同速度学习来稳定的。在设计智能体 LLM 解决方案时，了解此类稳定化方法是有益的。
